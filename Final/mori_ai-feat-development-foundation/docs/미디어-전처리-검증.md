## 구현

- 프론트: 안전하게 해석 가능한 JPEG/PNG,12MP 이하를 한 장씩 준비한다. 방향 보정·최대 변4096·WebP품질0.9, 확대/크롭 없음. 실제 WebP이며 더 작을 때만 채택한다. EXIF촬영일/시간대와 방향 보정한 원래 크기·File.lastModified를 유지하고, 확정한 File/예약 body/key/해시를 재시도에 재사용한다.
- 미지원 인코더·HEIC·큰 사진·ICC/XMP/검증되지 않은 색상 메타데이터 등은 원래 파일로 서버 처리한다. 원본을 별도로 보관하기 위한 추가 업로드는 없다. 준비를 모두 마친 뒤 기존 원자적 일괄 예약을 사용한다.
- 서버: 실제 디코딩·픽셀·용량·해시·신고 비율을 검증한다. 기본 손실WebP품질90이며 큰 픽셀 버퍼를 일찍 축소·해제한다. 최대40MP·20MiB와512MiB child 보호를 유지한다.
- 서버 최초 정규화는 전처리 WebP에도 한 번 적용한다. WebP내 decoder가 무시하는 payload를 그대로 보존하는 문제가 독립 검토에서 재현되어 무조건 bytes 채택 최적화는 제거했다. 전송량/입력 픽셀 감소가 주 이득이고 서버 인코딩 완전 제거를 의미하지 않는다. 검증된 normalized는 이후 생성·재시도에서 재사용한다.
- 새 예약만 source_lifetime=temporary를 동결한다. normalized/썸네일·메타데이터 영속화와 ready commit 뒤 source 파일만 정리한다. 증빙 행/해시/업로드 수신 용량은 유지해 complete재시도·생성 접수·소유권 검사를 보존한다. 늦게 다시 PUT된 파일도 tombstone sweep으로 정리한다. 기존 데이터 일괄 삭제 없음.
- 신규 변환기버전2, 과거 예약버전1. backend/media/normalize_v1.py는 이 저장소68aff30의 변환기를 그대로 보존한다. 이전 작업이 파일 저장 후 DB commit 전에 중단되어도 동일 bytes로 복구한다. 별도 moriai 저장소의 코드 이식은 없다.

- 최종 분리 재검증: 성능 비교 1 passed (`/tmp/mori-media-v16-performance-recheck.log`), 병렬 안정성 전체와 snapshot 설정 검사 4 passed (`/tmp/mori-media-v16-final-recheck.log`). 전체 실행에서 발생한 실패 항목은 모두 재검증을 통과했다. 단일 전체 실행에서 842개가 동시에 통과했다고 표현하지 않는다.
