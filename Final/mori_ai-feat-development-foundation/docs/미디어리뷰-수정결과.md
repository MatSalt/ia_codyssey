## PNG 색상 정책

- CRC/길이/중복 색상 chunk/색상 chunk의 IDAT 이후 배치/필수 IHDR·IEND 경계를 먼저 확인하고 Pillow `verify()`와 실제 `load()` 검증도 유지한다. CRC 손상·잘못된 chunk 길이·중복 gAMA·CRC가 유효하지만 잘못된 deflate는 `IMAGE_DECODE_FAILED`다.
- 원시 IHDR bit depth>8은 RGB/RGBA를 포함해 명시적으로 거부한다. cICP는 검증 범위인 sRGB `(primaries=1, transfer=13, matrix=0, full_range=1)`만 허용하고 그 외는 명시적 변환 실패다. PQ/HLG는 ICC/sRGB가 있어도 거부한다.
- SDR 색상 우선순위는 **유효 iCCP → sRGB → sRGB cICP → gAMA/cHRM → 선언 없는 sRGB 가정**이다. iCCP는 CMS를 실제 실행하며 읽히지 않거나 입력 모드와 맞지 않는 profile은 실패한다. sRGB 선언은 rendering intent 0~3만 허용한다. 상위 선언이 있으면 하위 fallback gAMA/cHRM은 사용하지 않는다.
- fallback cHRM은 검증된 표준 sRGB/D65 chromaticity `(31270,32900,64000,33000,30000,60000,15000,6000)/100000`만 허용한다. 다른 cHRM은 matrix를 추정하지 않고 명시적 실패다. 비-sRGB cHRM 변환 지원을 추가한 것이 아니다.
- gAMA 값은 양수이며 최대 10까지 처리한다. 색상 sample에 `linear = encoded ** (1/gamma)` 후 sRGB piecewise transfer를 적용한다. 표준 PNG fallback `gAMA=0.45455`는 sRGB 근사 선언으로 인식해 그대로 유지한다. alpha는 LUT/CMS에 입력하지 않는다. palette는 RGB 색상 확장과 투명도 분리를 거친다.
- metadata는 색상 변환 후 제거한다. 원본 bytes/SHA-256, 20MiB/40MP 제한, EXIF 8방향, 정확한 3:4 분기, 크롭 없는 축소, 무손실 WebP 정책은 유지한다.

## 출처와 생성물

기존 `moriai` 코드·OS ICC·인터넷 ICC·사용자 사진을 복사하지 않았다. 새 fixture는 이 저장소에서 작성한 `backend/tests/media/color_fixtures.py`의 원본 합성 데이터이며 복사된 제3자 자산이 없다.

- CMYK ICC는 LittleCMS 공개 C API로 만든 input profile(4채널→D50 Lab 3채널 CLUT)이며 자체 analytic CMYK 함수로 채웠다. 실제 프린터 calibration/현실 색상 재현 보증 자료가 아니다.
- gray ICC는 LittleCMS `cmsCreateGrayProfile`에 D50 white point와 gamma 2.2를 전달해 생성했다. LA는 동일 gray ICC와 별도 alpha=100을 사용한다.
- LittleCMS는 기존 Pillow에 포함된 라이브러리를 **테스트에서만 ctypes로 호출**한다. 새 runtime dependency·패키지 설치·image rebuild 없음. 프로필 파일이나 LittleCMS 구현 코드를 복사하지 않았으며 생성 코드와 수치가 저장소에 포함돼 있다.
- `tests/fixtures/media/color-review/`에 CMYK/L/LA ICC 입력 3개, 선형 PNG 4개, 16bit truecolor 2개, cICP PQ/HLG 2개, 비-sRGB cHRM 1개와 SHA-256 manifest를 저장했다. 기존 fixture/manifest는 그대로 유지했다. 기존 정상 fixture와 새 fixture의 checksum/원본 bytes 보존을 테스트한다.
