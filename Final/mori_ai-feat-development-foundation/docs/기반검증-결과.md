## 구현과 인계 경계

- `backend.main.create_app(static_dir: Path | None = None)`와 `GET /health` → `{"status":"ok"}`.
- API·assets·media·health namespace와 없는 파일 형태의 경로는 SPA fallback에서 제외한다.
- `Settings`는 필수 `DATABASE_URL` (`postgresql+asyncpg`), 절대 `STORAGE_ROOT`, 현재 지원 `STORAGE_MODE=local`, 유한한 양수 `WORKER_POLL_SECONDS` (최대 60초)를 검증한다. web lifespan과 worker 시작 시 같은 설정을 검증한다.
- worker는 signal-safe idle loop다. 실제 DB polling/claim/task 실행은 Task 3의 소유다. `backend/worker/__main__.py`를 Task 3에 인계한다.
- Compose는 PostgreSQL 17, web, worker와 project별 `postgres_data`/`media` named volume을 사용한다. 같은 project 안의 web/worker만 media를 공유한다. DB는 호스트에 공개하지 않는다.
- `.env.example`을 `.env`로 복사하고 새 개발 전용 비밀번호와 고유 `COMPOSE_PROJECT_NAME`/`WEB_PORT`를 설정한다. 비밀번호를 URL에 넣으므로 URL-safe 문자로 선택하거나 URL 인코딩한다. 비밀 기본값은 없다.
- `make up`, `make down`, `make verify-install`, `make verify-isolation`을 제공한다. down은 볼륨을 보존하고 검증용 isolation 스크립트만 자신이 만든 project의 볼륨을 제거한다.

## 설정 선택과 제약

- Ruling: 사용자 지시대로 README·검증계획은 직접 편집하지 않고 이 보고서를 총괄에게 인계한다.
- Ruling: 테스트 의존성은 별도 `requirements-dev.lock`까지 hash lock한다. runtime에 pytest를 넣지 않으면서 clean test stage를 재현하기 위한 추가 파일이다.
- Ruling: FastAPI는 `>=0.115,<0.130`에서 resolve한다. 최신 범위의 TestClient가 httpx2로 전환하는 deprecation을 확인하여 계획의 httpx 기반 조합을 유지한다. 실제 patch는 아래 최종 목록에 기록한다.
- Ruling: R2는 실제 adapter가 구현되지 않았으므로 이번 기반에서 `storage_mode=r2`를 시작 시 거부한다. 새 계정·secret·adapter가 준비되면 후속 연동 범위에서 확장한다.
- host Node 23과 기존 서비스는 변경하지 않았다. Docker/Orca 소켓은 sandbox에서 거부되어 승인된 `require_escalated` 호출로 실행했다. 앱 재시작 없음.
- 이번 통과는 로컬 기반 V01 범위다. HEIF/HDR 실제 변환, DB 실행권·복구, OAuth, AI, R2, 배포 검증을 뜻하지 않는다.

## 총괄 및 다음 담당자 인계

1. README에는 `.env.example` 복사·새 개발 비밀번호·고유 Compose project/port 설정 후 `make up`/`make down`, 검증은 `make verify-install && make verify-isolation`을 반영한다. 검증계획 V01은 위 실행 근거로 성공 처리 가능하다.
2. media 담당은 `backend/media/`, `backend/tests/media/`와 계획의 fixture/scripts만 편집한다. 현재 Pillow/pillow-heif가 runtime image에 설치돼 있다. 실제 codec/HDR·메모리 검증은 아직 미실행이며 Task 2가 담당한다.
3. DB/worker 담당은 `backend/database.py`, models/migrations, generation, worker runner/jobs 및 `backend/worker/__main__.py`를 이어받는다. `Settings.database_url`은 SQLAlchemy asyncpg URL이다. Compose 서비스 hostname은 `postgres`, user/db는 새 개발 설정을 사용한다. 테스트 연결도 운영 DB 없이 임시 PostgreSQL 17 project로 만든다.
4. 두 담당자는 manifest·lock·Compose·Makefile을 직접 동시 편집하지 않는다. 새 의존성이나 target은 총괄에게 요청한다. 현재 image를 사용할 때는 `MORI_IMAGE=mori-ai:verify` 또는 `docker run --rm --platform linux/amd64 mori-ai:verify-tests python -m pytest -q`로 접근 가능하다. 새 코드 실행에는 image rebuild 또는 자신이 소유한 코드 경로만 명시적으로 mount한다.
5. lock 재생성 명령은 Node 24 컨테이너에서 `npm install --package-lock-only`, Python 3.12/amd64 Bookworm에서 `pip-compile --generate-hashes --resolver=backtracking --output-file=backend/requirements.lock backend/requirements.in` 및 dev 대응 명령이다. 기존 서비스 파일 복사 없이 신규 resolve했다.
