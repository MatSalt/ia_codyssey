## 구현과 후속 인터페이스

`create_app(static_dir=None, *, settings=None, session_factory=None)`는 기존 static_dir 지원과 lifespan Settings 검증을 유지한다. 내부 생성 session factory의 engine은 app lifespan 종료 시 dispose하며 주입된 factory는 호출자가 소유한다. `request.app.state.settings`와 `request.app.state.session_factory`를 다음 router에서 사용한다.

`backend.http.security.require_user(request)`는 `AuthContext(user_id, session_id)`를 반환한다. `require_csrf(request, context)`는 Origin 정확 일치와 세션에서 유도된 CSRF를 검사한다. 후속 변경 endpoint는 인증 dependency와 CSRF 검사를 함께 적용해야 한다. `backend.http.errors.APIError(status, code, message=..., *, details=None, retryable=False)`와 `envelope(request, data)`를 공통 응답으로 사용한다. 공통 middleware가 API 응답의 no-store와 새 request_id를 부여한다. `StrictBody`는 extra=forbid이고 검증 오류 응답은 원문 입력·쿠키·토큰을 포함하지 않는 422 VALIDATION_ERROR다.

개발 로그인은 `APP_ENV=local`, `DEV_AUTH_ENABLED=true` 두 조건에서만 동작한다. `POST /api/dev/login` body는 `{"account":"alpha"}` 또는 `{"account":"beta"}`이고 정확한 APP_ORIGIN의 Origin header가 필요하며 성공은 body 없는 204 및 세션 cookie다. 이후 `/api/v1/me`로 사용자·동의·CSRF를 가져온다. 실제 Google/Kakao callback·redirect는 제공하지 않는다. `/api/dev/config`는 envelope data에 `dev_auth_enabled`만 반환하며 `/api/v1/client-config`는 기존 공개 필드를 유지한다.

개발 HTTP로 실행하려면 `APP_ENV=local`, `DEV_AUTH_ENABLED=true`, `SESSION_COOKIE_ALLOW_INSECURE_LOCAL=true`를 명시한다. `APP_ORIGIN`은 실제 UI origin과 포트를 정확히 지정한다(예: `http://127.0.0.1:8000`; localhost는 별도 origin). `.env.example`의 dev auth와 insecure cookie 기본은 false이며 Compose의 기본 APP_ENV는 production이다. wildcard·path가 붙은 origin은 거부한다. production+dev auth 및 local 외 insecure cookie는 설정 실패다. Docker 포트 바인딩은 기존 127.0.0.1을 유지했다.

cookie는 `mori_session`, HttpOnly·SameSite=Lax·Path=/·Max-Age(개발 기본 86400초)다. Secure는 기본 true이며 local 환경에서 명시 opt-in한 HTTP 예외만 false다. 세션은 `secrets.token_urlsafe(32)`로 생성하고 DB에는 SHA256 hash만 저장한다. CSRF는 raw session token과 domain separator `mori-ai:csrf:v1`의 SHA256로 유도해 `/me`에서만 노출한다. logout은 현재 세션 철회 후 cookie 삭제·204다. 만료·철회·삭제 사용자 세션은 401 AUTH_REQUIRED로 거부한다.

동의 정책 기본은 `local-2026-10-16`이며 `CONSENT_POLICY_VERSION` 설정을 사용한다. 고지에는 원본/정규화본 비공개 보관·AI 처리·비동기 삭제·복구 및 이력 보관 예외·실제 외부 AI 미호출을 포함했다. `POST /api/v1/consents`의 현재 정책+고정 purpose+agreed=true만 허용하고 동일 동의는 최초 201 뒤 200으로 같은 agreed_at을 반환한다. 실제 운영 OAuth/동의 정책의 확정을 대신하지 않는다.

## migration

0002는 auth_identities/sessions/consents/idempotency_records와 unique/FK/index를 추가한다. auth_identity provider는 google/kakao만 허용한다. synthetic 계정은 unique nullable `users.dev_account` 내부 표식으로 PostgreSQL ON CONFLICT 조회/생성하며 이메일 자동 병합이나 fake provider는 없다. consent 역시 unique conflict로 동시 요청을 하나의 이력에 수렴시킨다.

album의 order_mode/next_selection_index/cover/active_run/updated_at/published_at, page의 source/normalized/thumbnail 참조와 비율·AI 글귀·촬영/정렬·편집시각, upload의 file_last_modified_at, run의 시작/종료시각을 추가했다. idempotency의 resource_id는 operation별 다형 참조이며 특정 테이블 FK를 임의로 지정하지 않았다. 요청 hash 충돌·멱등 replay HTTP 구현은 Task 2 소유다.

Ruling: 기존 최소 seeded·저장 행 호환성을 위해 source_asset_id·sort_date·sort_date_source는 nullable이며 album order_mode/date와 next_selection_index/1은 server default다. 실제 업로드의 값 채움과 public ready의 필수성 검사는 후속 application 담당자가 보장한다. 과거 제품의 완전한 ready 행 backfill을 수행한 migration으로 주장하지 않는다.
