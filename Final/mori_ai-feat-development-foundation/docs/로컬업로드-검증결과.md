## 구현 경계

예약은 album 행 잠금 아래 최신 동의·draft·version·1~50개·20MiB·300MiB·기존 활성 슬롯을 원자 검사한다. 실패/만료도 제거 전까지 슬롯을 차지하고 declared bytes 예약은 해제된다. 각 선택은 서버 UUID와 단조 selection_index를 받고 source/page/upload가 같은 transaction에 생성된다. client_file_id 중복은 422, 지원 확장자는 대소문자 무관이며 빈 MIME·octet-stream HEIC를 받는다. 실제 형식과 디코딩은 worker가 판단한다. 여섯 media 설정과 snapshot version 1·예약 당시 upload MIME을 JSON에 보존한다.

기존 Idempotency helper를 사용한다. 같은 owner/정규 operation/key는 기존 status/data를 version 검사보다 먼저 재생하고 request_id는 새로 만든다. hash가 다르면 409, album 소유권·삭제 검사는 재생 전에도 수행한다. unknown body/query는 422이며 API 응답은 공통 envelope/no-store/request_id를 따른다.

로컬 key는 `owner_uuid/album_uuid/page_uuid/role`이다. filename을 경로에 사용하지 않는다. PUT은 chunk 단위로 최대 20MiB 및 declared bytes 일치를 검사한다. 임시 파일 fsync 뒤 atomic hard link로 확정하여 기존 원본을 교체하지 않는다. 동일 크기·SHA256 bytes 재전송은 204, 다른 bytes는 409다. 동시 동일 PUT도 하나의 원본에 수렴한다. 원자적 no-replace 동작을 위해 POSIX rename의 덮어쓰기 대신 link/unlink를 사용했다.

예약 URL은 900초이며 세션 credential을 query에 넣지 않는다. 서버 Content-Type은 required_headers에 고정하고 변경 요청의 현재 세션 CSRF/Origin은 별도 보안 헤더로 검사한다. 예약 당시 CSRF를 응답에 고정하지 않으므로 같은 owner 재로그인도 기존 URL과 최신 CSRF로 재전송한다. 소유자 없는 private URL과 다른 owner URL은 404다. PUT 후 삭제/만료 경합을 재검사하며, complete가 이미 접수된 파일을 PUT 마무리 과정이 삭제하지 않는다.

complete는 immutable 원본의 존재·크기·checksum 확인을 파일 I/O transaction 밖에서 수행한 뒤 album 상태를 재검사하고 validating+job을 원자 기록한다. 최초 접수 `now >= expires_at`는 expired, validating 반복은 202, terminal 반복은 200이다. PUT만으로 ready가 되지 않는다. validating 이후 URL 만료는 검증·복구 source를 삭제하지 않는다.

worker는 `JobClaim`과 DB 현재 fence/lease를 사용한다. heartbeat는 독립 session이며 파일 I/O·subprocess 대기에서 DB 잠금을 유지하지 않는다. `normalize_in_process(config=...)`에 보존 설정을 전달하고 부모 env를 변경하지 않는다. subprocess timeout/cancel reap은 기존 media 구현을 사용한다. source checksum을 정규화 전후 확인하고 파생 파일은 deterministic key에 fsync/no-overwrite 저장한다. normalized/thumbnail SHA는 각 파일 bytes로 따로 계산한다. 파생본 저장 후 album·page·owner·source 연결·job fence/lease를 다시 검사해 ready를 연결한다. 명시적 이미지 거절은 upload=rejected/job=failed terminal이다. source bytes는 재인코딩하지 않는다.

EXIF 현지 naive 시각의 유효한 달력 날짜만 사용하고, 잘못된 날짜는 File.lastModified를 Asia/Seoul로 변환한 값, 다음으로 예약시각을 사용한다. captured raw/timezone은 원문을 보존한다. sort_date_source는 계약의 exif/file_modified/reserved_at이다. batch 전체 terminal 시 date 모드는 ready 날짜/selection tie 순, 다른 상태는 selection 순이다. manual은 이후 완료/추가에도 유지하며 새 페이지는 뒤에 붙는다. 재정렬은 임시 음수 위치 flush 후 연속 양수 위치 flush로 unique 충돌을 피한다.

media-access는 연결된 ready normalized/thumbnail/result만 300초 URL을 발급한다. normalized는 draft/processing/action_required에서만 허용한다. 모든 GET에서 owner/album/page/role/ready/deleted와 서명을 다시 검사한다. source·transform_output의 공개 GET 또는 URL 발급은 없다. 책장/상세 DTO도 같은 범위를 확인하고 현재 첫 활성 페이지 cover 및 실제 썸네일 URL을 제공한다.

cleanup은 DB FK 행을 삭제하지 않고 status/deleted_at을 기록하고 자신의 canonical 파일만 지운다. 삭제된 album의 같은 owner/album/page asset만 정리하며 stale cleanup fence도 거부한다. 활성 Page/Task/Attempt 참조는 보존하고 attempt JSON result envelope는 건드리지 않는다. 삭제 직전 저장된 아직 DB 미연결 normalized/thumbnail도 deterministic namespace에서 정리한다.

24h scanner는 예약시각 기준이며 900초 URL 기한과 별개다. reserved/expired/rejected만 재검사하고 진행 중 validation job이면 보존한다. reserved는 expired로 전환하고 cleanup_asset을 멱등 예약한다. validating·lease 복구 source·ready·generation unknown에 필요한 ready source는 삭제하지 않는다. 정리된 asset은 후보 query에서 제외하여 다음 scan 페이지로 진행한다. terminal 업로드 status는 source bytes 정리 후에도 조회할 수 있고 페이지 슬롯은 사용자 제거 전까지 남는다. 7일 초안/ready 원본 수명 정책으로 확대하지 않았다.

## 미실행과 완료 경계

실제 OAuth·R2·OpenAI 호출·배포·브라우저 통합은 실행하지 않았다. 실제 iPhone HDR/10bit tone mapping은 여전히 미지원이며 synthetic 16bit PNG가 IMAGE_NORMALIZATION_FAILED로 거절되는 것을 확인했다. 8bit synthetic HEIC 성공을 전체 HDR/HEIC 지원 완료로 확대하지 않는다. 기존 media subprocess timeout/memory/cancel reap 검사는 전체 backend 회귀에 포함한다.

추가 agent·독립 리뷰·Git 작업은 수행하지 않았다. 작성자의 자체 검토 뒤 총괄이 독립 합류 검토·브라우저·통합/commit을 담당한다. AI generation endpoint와 fake AI 결과는 구현하지 않았다.
