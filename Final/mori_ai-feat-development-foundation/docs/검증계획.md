# 사진첩 검증 계획과 미결정 사항

- 정리일: 2026-10-16
- 상태: 요구사항 점검과 설치·호환성 검증 계획 통합. 제품 테스트 결과가 아님
- 기준: [기능요구명세서](../기능요구명세서.md), [공통계약 v1.3](공통계약-v1.md), [샘플 JSON](공통계약-v1.examples.json), [설계](설계.md)

D01~D13은 보완·결정 목록, A01~A16은 인수 기준, F01~F13은 실패/동시성 시나리오, V01~V10은 실제 실행 검증 계획이다. 번호는 원 조사와 대응하도록 유지한다. 미결정 사항과 미실행 검증을 완료로 표시하지 않는다.

## 1. 기준과 과거 표현 정리

현재 지시 → 확정 사용자 요구 → 최신 공통계약·샘플 순으로 해석한다. 아래 표는 정리 전 문서에 남아 있던 표현이 어떤 현재 기준으로 해소됐는지 보여준다. 상세 근거는 [통합 전 상세설계](archive/2026-10-16/상세설계.md)와 [통합 전 명세](archive/2026-10-16/기능요구명세서.md)에 보존한다. 설계의 추가 보완안은 현재 계약과 구분한다.

| 과거 표현 | 현재 적용 기준 | 판정·근거 |
|---|---|---|
| HEIC는 배포 검증 후 지원 여부 결정 | HEIF/HEIC 초기 필수, 지원 제거 대신 decoder 검증 실패를 배포 실패로 처리 | 최신 사용자 결정. 계약 1·2.3·8절 우선 |
| 빈 글귀 미정, 저장 방식 미정 | AI 빈값 실패, 사용자 빈 문자열 허용, 페이지별 저장 버튼 | 계약 1·4.2·7절, JSON `client_config.data.caption_allow_empty` |
| 글자 수·용량 수치 미승인이라는 본문 | 80자·AI 목표 20~45자, 1~50장, 20MiB/300MiB/4천만 픽셀 | 통합 전 상세설계 10·11절에서 승인, 계약 2.1·4.3절로 구체화 |
| 제목 PATCH, 단일 active_stage 예시 | 제목 변경 API 없음, tasks별 진행 표시 | 통합 전 상세설계 5절의 과거 예시 대신 계약 3.1·4.2·4.4절 |
| 제작자 감상/NFC 예외 미정 | 로그인한 소유자 감상, 공유·NFC 제외 | 계약 1절. 명세 3.5절은 현재 인수 범위 아님 |
| 정규화 JPEG/PNG | normalized·AI 출력·result·thumbnail WebP | 계약 8절에서 v1.1 대체 명시 |
| 이미지 모델 소량 검증 후 선정 | GPT Image 2 기본 모델, 사용자 품질 확인을 개발 시작 전 반복하지 않음 | 계약 1·7절. 운영 시간·비용·timeout·실제 adapter 식별자 검증은 남음 |
| action_required에서 완료로 가는 화살표 누락 | 원래 unknown 결과 회수로 전체 완료 시 review_ready 가능 | 통합 전 상세설계 4절 표보다 계약 3.1~3.2절 우선 |

제품 범위는 기능요구명세서, 현재 구현 계약은 공통계약, 기술 목록·버전·worker 보완 제안은 설계에서 관리한다. 이 검증계획의 D/A/F/V 항목은 그 기준을 어떻게 결정·검증할지 정의하며 기술 승인이나 실행 성공을 대신하지 않는다.

직접 모순 대신 주의할 계약 해석: 공개 Page.source는 원본 source가 아니라 normalized 메타데이터다(계약 2.4). published 샘플에 해당 메타데이터가 있어도 source 원본 다운로드 허용이나 normalized signed URL 발급 허용을 뜻하지 않는다(4.2). 삭제 샘플은 AlbumDetail(status=deleted)이 아니라 404 오류이며 정상 조회에서 삭제 상태 본문을 기대하면 안 된다.

## 3. 기술 중립 인수 기준

각 기준은 스택·큐 사업자가 바뀌어도 유지할 관찰 가능한 동작이다. 다음은 **작성한 검증 설계**이며 실행 결과가 아니다. 외부 과금 exactly-once를 인수 조건으로 삼지 않는다.

V10은 자동 Playwright 부분과 실기기 수동 부분을 함께 보고한다. 자동 명령의 exit=0만으로 수동 모바일·HDR 검증을 완료로 표시하지 않는다.

### 소량 실제 AI 확인 순서

| 순서 | 입력 | 기대 호출과 결과 |
|---|---|---|
| 1 | 방향 적용 후 정확한 3:4 사진 1장 | 이미지 호출 0, 글귀 호출 1, WebP 결과·별도 본문 표시 |
| 2 | 가로·정사각 사진 각 1장 | 각 이미지 호출 1, 글귀 호출 1. 실제 WebP 결과가 정확한 3:4 |
| 3 | HEIC 원본 1장 | 업로드 서버 정규화 뒤 WebP만 두 AI port로 전달. 날짜·방향 보존, 원본 별도 보존 의무 없음 |
| 4 | 정상 결과 저장 후 로컬 저장/DB 실패 주입 | AI 추가 호출 0, 보존 파일로 완료 가능 |
| 5 | 5~10장 전체 사진첩 | 처리 시간·실제 확인 가능한 비용·사용량·최고 동시성 기록, review_ready까지 연결 |

호출 예산은 실행 전에 사용자 범위 안에서 설정한다. 불명확 비용은 0으로 기록하지 않는다. 응답 유실·정책 차단·다양한 timeout은 V04의 가짜 adapter에서 먼저 검증하며, 실제 반복 과금으로 실패 시나리오를 만들지 않는다.

