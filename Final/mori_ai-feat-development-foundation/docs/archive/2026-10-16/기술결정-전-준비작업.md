# 기술 구성 결정 전 준비 작업과 판단 기준

> 통합 전 이력입니다. 현재 기준은 [프로젝트 README](../../../README.md)에서 확인합니다.

- 작성일: 2026-10-15
- 상태: 문서 조사. 기술 구성 확정·제품 구현·패키지 설치·외부 연동 없음.
- 사용자 지시: 기술 구성 조사와 병렬로 재사용 조사 및 요구사항·검증 점검 진행.

## 1. 지금 유지할 기준

기술 구성 미결정은 제품 정책 전체가 미결정이라는 뜻이 아니다. [공통계약 v1.2](공통계약-v1.md)의 사용자 동작·DTO·오류 의미·상태·실패 복구 요구를 기준으로 조사한다. 특정 언어·프레임워크·DB·배포 제품을 선택해야 하는 항목은 별도의 기술 가정으로 분류한다.

현재 계약을 수정하거나 폐기하지 않는다. 기술 선택이 기존 계약에 영향을 주면 영향과 대응안을 제시한 뒤 명시적으로 갱신한다. 현재 문서의 구현 표현을 기술 선정 완료의 근거로 사용하지 않는다.

## 2. 제품 요구와 기술 가정 구분

HTTP 경로·JSON·상태 enum과 쿠키 세션·CSRF는 현재 계약에 이미 제시되어 있다. 이들은 프레임워크보다 독립적이지만 변경 비용은 존재한다. 기술 구성 조사를 이유로 자동 변경하지 않는다. GPT Image 2·WebP 등 기존 계약의 구체적 결정도 이번 조사에서 재선정하지 않는다. 실제 API 사용 가능성·지원 옵션은 실제 연동 전 확인할 별도 항목이다.

## 4. 조사 결과를 기술 선택에 사용하는 방법

아래 기준으로 후보 기술을 비교하되 현재 점수나 제품을 확정하지 않는다.

1. **필수 요구 충족:** HEIC 디코딩·WebP·OAuth·비공개 미디어·장시간 작업·영속 복구가 가능한가.
2. **재사용의 실제 비용:** 가져올 코드보다 제거할 결합과 새 계약 대응이 얼마나 큰가. 기존 언어가 같다는 이유만으로 전체 재사용을 선택하지 않는다.
3. **검증과 실행 비용:** 로컬 환경, 배포 환경, 실패 재현, 관측·복구를 어떻게 준비하는가.
4. **자원과 비용:** 50장 처리, decode 메모리, 작업 동시성, 외부 AI 호출·저장·전송 비용을 측정할 수 있는가.
5. **개발 일정과 숙련도:** 팀이 구현·운영·문제 해결할 수 있는가. 새 도구 학습 비용을 포함한다.

외부 제품의 현재 가격·지원 기능을 이 문서에서 단정하지 않는다. 선택 후보가 구체화되면 공식 문서와 실제 검증으로 근거를 보완한다.

## 5. 다음 작업의 경계

지금 계속할 수 있는 것은 보고서 보완, 화면 흐름·와이어프레임, 테스트 데이터 명세, 실패·경쟁 시나리오 정의다. 실제 샘플 파일을 확보할 때는 동의·권한이 있는 자료나 합성 자료만 사용하고 운영 사용자 사진을 복사하지 않는다.

제품 프로젝트 골격, dependency 설치, DB migration, 코드 이식, OAuth·storage·AI 실제 연결과 유료 benchmark는 기술 선택·실행 범위가 정해진 후 별도 Task로 진행한다. 이번 문서 조사 완료가 해당 실행의 승인으로 확대되지 않는다.

## 7. 조사 결과와 후속 우선순위

두 Task는 succeeded 완료 보고를 수신했다. 총괄은 보고서 본문과 주요 원본 근거를 확인했다. 요구사항 보고서에는 보완·결정 항목 13개, 인수 기준 16개, 실패·복구·동시성 시나리오 13개 및 테스트 자료 목록이 있다. 실제 테스트를 실행한 결과는 아니다.

1. 재사용 우선 후보는 OAuth 통신·storage I/O와 작은 순수 함수다. 인증 세션·생성 엔진·전체 책장/뷰어는 새 계약과의 차이가 커 구조 참고 후 신규 작성하는 방향을 검토한다.
2. 기존 이미지 optimizer의 crop·640×853 출력은 새 정확한 3:4 확장 계약을 대체하지 못한다. 기존 AI unknown 분류의 일부 retry/fallback 정책도 새 결과 불확실 재호출 금지와 달라 그대로 이식하지 않는다.
3. 기술 선택과 별개로 업로드 전 동의 검사, validating 작업의 장애 복구, unknown 원래 결과를 회수하지 못할 때의 절차, 혼합 실패 재개, 한 문장 판정 기준을 구체화할 수 있다. 보고서는 이 정책을 임의 확정하지 않았다.
4. 원본 Python manifest의 httpx 중복 버전 지정이 확인되었다. 전체 dependency 복사보다 채택 모듈만으로 새 manifest를 구성하는 편을 검토한다. 설치·호환성 검증은 하지 않았다.

Orca 완료 보고의 초기 전송은 작업자 샌드박스에서 runtime 연결 실패가 있었으나, 기존 Dispatch의 명령을 샌드박스 밖에서 재전송하여 두 Task 완료를 확인했다. worker-release 결과 요구사항 작업자는 released, 재사용 작업자는 Orca가 user_takeover로 retained를 반환했다. retained 터미널은 강제 종료하지 않았다. 완료 Delivery는 확인 처리했다.

제품 코드·공통계약·샘플 JSON 변경, 코드 이식, 의존성 설치, 실제 외부 연동, commit·push는 수행하지 않았다.
