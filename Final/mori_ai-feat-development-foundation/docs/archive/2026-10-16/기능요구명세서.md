- 작업 프로젝트: `mori_ai`

## 1. 목적과 범위

사용자가 사진을 간편하게 넣으면 AI가 이미지를 분석하여 페이지별 한 문장의 글귀를 생성하고, 사용자가 이를 직접 수정하여 사진첩을 만드는 서비스다. 사진 1장당 1페이지로 구성하고 사용자가 정한 순서를 유지한다. 사진첩은 모바일에서 사진 감상을 방해하지 않는 UI로 제공한다. 굿즈는 아래 별도 미확정 최소안으로만 검토한다.

현재 서비스의 핵심 기능은 사진첩 제작, 뷰어, 책장이다. 굿즈 디자인·미리보기는 전체 미확정이며 기본 예시 키링·내 이미지 기반 AI 키링 이미지 생성·주문하기 버튼의 최소안으로 검토한다. NFC 굿즈를 통한 사진첩 접근 제한은 보안 목표로 검토하며 구현 방식은 미정이다. 기존 `moriai`의 필요한 모듈을 선별 재사용하고, 뷰어는 별도로 제공된 추억책 UI를 참고한다. 기존 운영 서비스의 데이터·자격증명·인프라와 분리한다.

### 요구사항 표기

- **확정**: 사용자가 직접 지정한 요구사항.
- **제안**: 사용 흐름의 완결성과 안정성을 위해 검토할 요구사항. 구현 확정 사항이 아니다.
- **과제 필수**: 과제 원문에서 요구하는 항목. 구체적인 구현 방법은 별도 설계한다.
- **미정**: 추가 결정이 필요한 정책 또는 범위.
- **미확정 / 향후 확장 검토**: 현재 구현 범위에 포함하지 않으며, 추후 도입 여부를 검토하는 기능.

## 2. 기본 사용자 흐름

- 굿즈 흐름(전체 미확정): 기본 예시 키링 이미지 → 내 이미지 업로드 → 생성형 AI 키링 이미지 확인 → 주문하기 버튼. 버튼 이후 흐름은 미정이다.
- 사진첩 제작 흐름: 내 책장 → 사진 간편 첨부 → 날짜순 기본 정렬·사용자 순서 변경 → 이미지 분석·페이지별 한 문장 생성 및 AI 3:4 조정 → 글귀 확인·직접 수정 → 완성된 사진첩 관리. 처리 단계의 실행 순서는 상세 설계에서 정한다.
- 감상 흐름: 사진첩 열기 → 사진첩 감상. NFC 굿즈 태깅·접근 검증은 전체 미확정인 별도 검토안이다.

구글·카카오 로그인을 제공한다. 로그인 시점과 세션 정책은 미정이다. 사용자가 자신의 콘텐츠를 구분하여 조회할 수 있어야 한다.

#### AI 이미지 변환 정책

확정된 원칙은 다음과 같다.

- 모든 첨부 사진의 결과 비율은 세로 3:4다. 이미 해당 비율인 원본사진은 AI 확장을 생략하고 글귀 분석·최적화만 수행한다.
- 크롭이 아니라 생성형 AI를 활용하여 자연스럽게 변환한다.
- 그림체 선택은 초기 범위에서 제외하며 원본 사진의 실사 느낌을 유지한다.

다음 정책은 검토 제안이며 아직 확정되지 않았다.

- 주요 인물과 사물을 보존하고 부족한 영역을 자연스럽게 확장한다.
- 원본사진 선택 시 실사 느낌을 유지하면서 비율을 변환한다. 사용자에게 표시할 명칭은 별도 결정한다.
- 원본 파일과 변환 결과를 구분하여 저장하고, 원본 파일 자체는 변경하지 않는다.
- 이미 세로 3:4인 원본사진의 AI 확장 생략은 승인된 정책이다.
- 그림체 변환의 처리 방식은 향후 기능 채택 시 설계한다. 초기 구현에 포함하지 않는다.

#### 기술적 가능 범위

- **고정 URL을 담은 일반 NFC 태그:** 서버가 같은 URL의 태깅 접속과 복사 링크 접속을 신뢰성 있게 구별할 수 없으므로 실물 전용 접근 보장을 충족하지 못한다. 숨긴 URL이나 진입 경로 표시는 실물 소지 증명이 아니다.
- **보안 NFC 태그 + 서버 검증:** NXP NTAG 424 DNA 같은 태그는 읽기마다 암호학적 인증 메시지를 포함한 URL을 제공할 수 있다. 태그별 키 설정, 서버 검증, 카운터 재사용 차단, 제한된 감상 세션을 조합하는 설계를 검토한다. 특정 제품 채택을 확정한 것은 아니다.
- **남는 한계:** 인증 링크가 처음 사용되기 전에 전달되는 경우, 실시간 중계, 유효 세션 공유, 화면 캡처·이미 다운로드한 콘텐츠 복제까지 완전히 차단한다고 보장하지 않는다. 태깅 순간의 인증과 감상 내내 실물을 소지하는 것은 다른 조건이다.
- **브라우저 호환성:** 웹 NFC API는 지원 범위가 제한적이므로 모바일 운영체제의 NFC URL 열기와 브라우저 내 NFC 읽기를 구분한다. 실제 iPhone·Android에서 선택한 방식의 동작을 검증한다.

## 5. 주요 검증 시나리오

제안 요구사항이 승인되면 다음 시나리오를 상세 인수 기준으로 구체화한다.

1. 사용자가 만든 콘텐츠가 자신의 책장에 표시되고 다른 사용자에게는 노출되지 않는다.
2. 사진 50장까지 첨부할 수 있고 51장 이상은 제한을 안내한다. 사진 1장당 1페이지이며 사용자가 정한 순서가 유지된다. 최대 개수 변경 시 화면과 서버 검증이 일치한다.
3. 그림체·난이도·목소리 선택을 표시하지 않는다. 별도 제목·생성 전 확인 화면 없이 생성을 시작할 수 있다.
4. 가로·정사각형·세로 사진의 결과가 세로 3:4이며 크롭으로 대체되지 않는다. 자연스러움은 별도 품질 기준으로 확인한다.
5. TTS 생성 작업과 뷰어의 TTS 재생 기능이 없다.
6. 생성 중 새로고침하거나 책장으로 이동한 뒤에도 진행 상태를 조회할 수 있다.
7. 생성 요청을 반복 제출해도 같은 작업이 중복 실행되지 않는다.
8. 모바일 세로 화면에서 드래그와 화면 터치 각각으로 이전·다음 페이지를 넘길 수 있고 현재 페이지와 전체 페이지 수가 표시된다.
9. 배경음악을 켜고 끌 수 있고 자동재생 제한 시 직접 재생할 수 있다. 실제 iPhone에서 최초 재생 동작을 검증한다.
10. 이미지 처리 또는 미디어 로딩 실패 시 사용자가 다음 행동을 알 수 있다.
11. 모든 AI 글귀 생성 완료 후 결과 화면에서 페이지별 글귀를 수정하고 저장 결과가 뷰어의 별도 본문으로 반영된다. 글귀를 변경해도 이미지 픽셀은 변경되지 않는다.
12. **미확정 / 굿즈 최소안 채택 시:** 기본 예시 키링 이미지가 표시되고, 내 이미지를 업로드하면 생성형 AI가 해당 이미지 기반의 키링 이미지를 생성하여 보여주며, 주문하기 버튼이 표시된다. 클릭 이후 동작은 주문 경로 확정 후 검증한다.
13. **미확정 / NFC 보안 방식 채택 시:** 새 브라우저의 사진첩 직접 접속, 사용된 NFC 인증 링크 재전송, 미디어 직접 접근을 차단한다. 사용 전 링크 전달은 별도 위협 시나리오로 평가한다.
14. 최초 목록은 날짜순으로 정렬되며 수동 변경한 순서는 유지된다. 생성 진행 중에는 글귀를 수정할 수 없고 모든 AI 글귀 생성 완료 후 결과 화면에서 수정할 수 있다.
15. 완성 후 글귀를 수정하면 별도 본문에 반영되며 이미지 재생성은 제공되지 않는다.
16. 구글·카카오 각각으로 로그인할 수 있다. 세션 정책 확정 후 유지·로그아웃 시나리오를 추가한다.
17. 각 페이지의 이미지 분석을 통해 한 문장의 글귀가 생성되고, 사용자가 직접 수정할 수 있다. AI 글귀 재생성 기능은 제공되지 않는다.

굿즈 최소안과 NFC 보안 검토(시나리오 12·13), 그림체 선택, 자동 분류·선별과 영상 첨부·편집·재생은 현재 인수 대상이 아니다. 향후 도입을 확정할 때 별도 인수 기준을 작성한다.

## 10. 교육장 AI API 검토 메모

**최신 결정:** 교육장 API 사용은 필수 조건에서 제외한다. 아래는 이전 검토 기록이며 지원 불가를 확정한 것은 아니다. 상용 이미지 편집·분석 API를 독립 연동하는 방향으로 설계한다.

- [Codyssey 공개 API 학습자 매뉴얼](https://nimble-ceder-40b.notion.site/Codyssey-API-44817efd202c825a87670170c00e7f94)의 본문을 확인했다. 이미지 생성 endpoint와 base64 수신을 설명하지만 사진 입력·편집·배경 확장, chat 이미지 입력의 요청 계약은 확인되지 않았다. 지원 불가로 확정한 것은 아니다. 일부 삽입 이미지가 429로 표시되고 코드 블록이 로딩 상태여서 해당 자료까지 전부 검증하지 못했다.
- 매뉴얼의 사용량 탭은 호출 수·토큰·차감 토큰·잔여 토큰과 개별 호출 이력을 제공한다. 소량 테스트 시 모델별 실제 차감량을 이 기록으로 측정할 수 있다. 이미지당 정확한 차감 공식은 확인되지 않았다.
- 매뉴얼은 키의 본인 학습 용도 사용과 호출 감사 로그, 프롬프트·응답을 포함한 생성 콘텐츠의 기관 운영자 열람 가능성을 안내한다. 공개 배포 서비스에서 다른 사용자 사진을 처리하는 허용 범위, 데이터 보관·열람·삭제 정책은 교육장에 확인한다. 상용 운영 허용으로 해석하지 않는다.
- 사용자 제공 코드 예제로 확인한 계약(실제 호출은 하지 않음): Public base URL은 `https://copa.codyssey.kr`, OpenAI 호환 base URL은 `https://copa.codyssey.kr/v1`이다. 이미지 요청은 `POST /api/v1/images`, 인증은 서버에서 `Authorization: Bearer <virtual-key>`로 전달한다.
- 이미지 생성 예제는 `model`, `prompt`, `size`, `response_format` 필드를 사용한다. 예시 모델은 `gpt-image-1-mini`, 크기는 `1024x1024`다. 이 예제만으로 다른 모델·크기·사진 편집의 지원을 확정하지 않는다.
- `response_format: "b64_json"`을 지정하고 `result.images[0].b64_json`을 디코딩하여 이미지 본문을 받는다. 사용자 안내에 따르면 응답 URL은 웹 로그인 세션 전용이어서 API 키로 열 수 없다. API 서버 또는 worker가 base64를 디코딩·검증하여 서비스 저장소에 저장하고 뷰어에는 자체 권한 정책에 따라 제공한다. 교육장 결과 URL을 최종 미디어 주소로 사용하지 않는다.
- 제공 예제는 텍스트 프롬프트 기반 생성이다. 원본 이미지 전달 필드, 편집·확장 옵션, 이미지 분석 요청 형식, 사용량 필드는 포함되어 있지 않다. 따라서 사진 기반 변환과 페이지별 글귀 생성의 지원 여부는 아직 미검증이다.
- 사용자 제공 정보: 이번 달 5,000,000 토큰 사용 가능. 이미지 모델의 표시 차감 배수는 1. 제공 정보는 교육장 게이트웨이의 안내이며 직접 호출로 검증하지 않았다.
- 현재 필요한 핵심은 기존 사진을 입력으로 받는 이미지 편집·스타일 변환·세로 3:4 확장이다. 이미지 분석으로 페이지별 한 문장을 생성하므로 이미지 입력을 지원하는 텍스트 출력 모델도 필요하다. 교육장 chat endpoint의 이미지 입력 지원과 실제 모델 연결을 검증한다. TTS·영상은 초기 범위에서 제외한다.
- 후보: `gpt-image-2`, `gemini-2.5-flash-image`. 공식 제공자 기능과 교육장 `/api/v1/images`가 노출하는 기능은 다를 수 있다. 모델 목록만으로 편집 지원·3:4 지정 가능 여부를 확정하지 않는다.
- 추가 확인: 원본 이미지 전달 방식, 편집·마스크·비율·크기 옵션, 이미지 1장당 차감 계산, 실패 차감·사용량 조회, 동시 요청·속도 제한, 외부 배포 및 실제 사용자 사진 처리 허용 조건.
- 토큰 적정성: 실제 이미지 1장당 차감량을 c라 하면, 모두 변환하는 50장 사진첩 B개의 기본 차감량은 `50 × B × c`다. 재시도·개발 실험과 다른 AI 호출은 별도다. 차감 배수 1만으로 c를 알 수 없다.
- 상용 전환 제안: 화면과 핵심 생성 흐름에서 교육장 요청 형식을 직접 사용하지 않고 서버의 이미지 처리 경계에서 변환한다. 교육장 adapter와 상용 provider adapter를 교체할 수 있도록 모델·인증·요청/응답·사용량 단위를 구분한다. 생성 이미지는 서비스 저장소에 저장한다. 실제로 지원하지 않는 기능을 가짜 성공으로 처리하지 않는다.
- 실제 호출·정량 비용·생성 품질은 아직 검증하지 않았다. 교육장 API 문서 확인 후 허용된 샘플 사진 소량으로 품질·차감량·시간을 측정한다.

공식 기능 참고: [GPT Image 2](https://developers.openai.com/api/docs/models/gpt-image-2), [OpenAI 이미지 편집 API](https://developers.openai.com/api/reference/resources/images/methods/edit), [Gemini 2.5 Flash Image의 이미지 편집·비율 지원](https://developers.googleblog.com/en/gemini-2-5-flash-image-now-ready-for-production-with-new-aspect-ratios/).
