## 1. 조사 범위와 판정 기준

원본의 AGENTS.md·ARCHITECTURE.md·codebase map과 후보 파일의 import·인터페이스·초기 구현을 정적으로 확인했다. 전수 의존성 추적, 원본 테스트 실행, 실제 외부 연동, 성능·보안 검증은 하지 않았다. 아래 판정은 최종 이식 승인이나 동작 보증이 아니다.

| 판정 | 의미 |
|---|---|
| 수정 후 이식 후보 | 제한된 코드를 가져오되 설정·계약·의존성을 수정해야 함 |
| 구조 참고 후 신규 작성 | 기존 코드의 결합이 크거나 새 계약과 달라 설계·검증 경험을 참고 |
| 제외 | 사진첩 v1 범위에 포함되지 않음 |

현재 **그대로 복사해 사용 가능하다고 확정한 모듈은 없다.** 대상 경로는 제안이며 개발 기반 단계에서 확정한다. 필요한 외부 패키지 버전과 라이선스는 실제 이식 직전에 원본 manifest·lockfile·고지 파일로 확인한다.

미디어의 HEIF/HEIC 디코딩·촬영일·방향·색상·WebP 정규화는 기존 storage 코드만으로 충족되지 않는다. 관련 원본 구현이 있는지 추가 검색하고, 없거나 새 계약과 다르면 신규 작성한다. 글귀 생성 adapter 역시 이번 조사에서 재사용 가능한 전용 구현을 확정하지 않았다.

## 4. 가져오지 않을 범위

- payment·credits·TTS·fiction 추천·설문·notification·mobile native·Apple 로그인·관리자 기능 전체.
- 원본의 `.env`, 운영 계정, 인증 토큰, storage 객체, 실제 사용자 사진·DB 데이터.
- 기존 Alembic migration 체인과 storybook schema 전체.
- 공유·NFC·영상 export·자동 낭독·hotspot·단어 TTS 등의 뷰어 확장 기능.
- 원본 backend/frontend manifest·lockfile·Compose·배포 workflow 전체 복사.

공통 유틸리티가 제외 기능을 import하면 필요한 부분을 분리하거나 신규 작성한다. 작게 필요한 기능 하나 때문에 기존 제품 도메인 전체를 가져오지 않는다.

## 5. 후속 조사와 담당 순서

1. **백엔드 담당:** R01~R04의 전체 호출 경로·config·테스트를 확인하고 인증·미디어 기반의 최소 이식 범위 제안.
2. **프론트엔드 담당:** R08~R11의 제스처·미디어 실패 처리 등 작은 순수 기능을 추려 신규 화면 구성과 비교.
3. **AI·worker 담당:** R05~R07의 복구·failure evidence·result persistence 패턴을 새 task/attempt 모델에 대응.
4. **기반 담당:** R12의 함수별 의존성을 추적하고 새 로컬 runtime에 필요한 최소 기능 결정.
5. **총괄:** 각 제안의 코드량·추가 의존성·검증 비용을 비교해 최종 판정·대상 경로·파일 소유권 확정.

조사는 읽기 전용으로 시작한다. 구현 단계로 넘어가기 전 후보별 기록을 갱신하며 원본 HEAD가 달라졌으면 diff와 새 기준을 기록한다.
