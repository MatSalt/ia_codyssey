# Real AI implementation plan

> **For agentic workers:** Use executing-plans with the assigned Orca Task; shared checkout ownership below is exclusive. User approved execution through remaining items 1–6; no additional approval gate for routine implementation.

**Goal:** Connect real captions/images with durable spending control and demonstrate upload → generation → edit → publish/viewer and safe recovery.

**Architecture:** PostgreSQL holds a global validation budget and one reservation per attempt. OpenAI SDK adapters use zero automatic retries; durable original result recovery never resubmits an ambiguous request. Existing R2 media validation, owner checks, leases and fencing remain authoritative.

**Tech Stack:** FastAPI, SQLAlchemy/asyncpg, OpenAI Python SDK, Pillow, R2, React.

**Spec:** ../../공통계약-v1.md, ../../상세설계.md and user's approval through items 1–6 on 2026-10-16.

## Global Constraints
- Existing user data and current QA database remain intact. No production deployment.
- Caption model gpt-5.4-mini, replaceable through settings with reviewed pricing profile. Image gpt-image-2. No silent model fallback.
- Total authorized validation budget $100; initially available cumulative budget $5. Decimal USD; reservations plus settled costs count toward cap, including unknown calls.
- Persist a reservation BEFORE every paid call. Unique attempt prevents duplicate dispatch. Never release unknown/timeout reservations. Database reset is not a budget reset procedure.
- Exact portrait 3:4 skips image API; caption uses original normalized image. Other images request 768x1024 WebP, n=1, medium quality; verify result before accepting. No cropping or style changes requested.
- SDK max_retries=0; captions maximum 256 output tokens, no tools/background. Images single normalized input; fixed bounded prompt. Unknown responses do not automatically regenerate.
- No real provider calls by workers; coordinator alone performs minimal synthetic QA after tests/review.

## Review Focus
- Concurrent budget reservations cannot overspend or dispatch one attempt twice (ledger integration tests).
- Provider timeout, cancellation and process death retain reservation and never trigger repeat paid calls (executor/runner tests).
- Input storage failure before dispatch is safe to retry; failure after provider response recovers original output only (executor tests).
- Wrong dimensions, invalid caption, missing usage and deletion during response cannot publish invalid content or lose financial accounting (provider/executor tests).
- Fake/real mode switching cannot execute old runs under another model or enable a fake badge for real output (admission/frontend tests).
