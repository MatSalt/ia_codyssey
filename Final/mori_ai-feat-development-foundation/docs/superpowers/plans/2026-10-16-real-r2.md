# 실제 R2 adapter 구현·검증 계획

> **For agentic workers:** 기존 사용자 지정 Orca Run→Task→worker-start→완료 보고를 사용한다. 이번 사용자 요청은 앞서 제시한 R2 여섯 단계의 구현·검증을 명시적으로 승인했다. 새 기능 범위를 추가하지 않고 필요한 storage 교체와 검증을 진행한다.

**Goal:** 새 비공개 R2 bucket으로 업로드·정규화·URL·삭제·복구를 연결한다.
**Architecture:** 기존 canonical UUID object key를 환경별 prefix 아래에 보관한다. R2가 원장이고 로컬 파일은 bounded decoder cache다. 서명 PUT에는 Content-Type·If-None-Match 및 transport Content-Length를 묶고, 응답 유실 재시도의 412는 complete의 SHA256 대조로 해결한다.
**Tech Stack:** 기존 Python3.12/FastAPI/SQLAlchemy/Pillow/httpx/React와 boto3. root가 Linux Docker에서 잠금 파일을 갱신한다.
**Spec:** docs/설계.md storage/worker, docs/공통계약-v1.md 미디어·멱등·소유권·MediaStoragePort, V06 검증계획.

## 범위와 결정

- CORS는 docs/storage/r2-cors.local.json의 dashboard 배열 형식. 현재 APP_ORIGIN=http://127.0.0.1:8000, WEB_PORT=8000. wildcard와 localhost 대체값을 추가하지 않는다. 사용자가 콘솔에 적용하며 총괄이 임의 변경하지 않는다.
- 공개 bucket을 만들지 않는다. 브라우저에는 S3 secret·앱 session/CSRF를 R2로 보내지 않는다.
- 원본 최대20MiB/전체300MiB/40MP, 최초 complete900초, 읽기 URL300초, 기존 소유권·삭제·fence 규칙 유지.
- direct PUT required_headers에는 Content-Type와 If-None-Match:*를 반환한다. 브라우저가 File body 길이로 보내는 Content-Length는 서명에 고정하되 JS forbidden header로 직접 설정하지 않는다.
- complete 요청에 optional sha256(64 lowercase hex)를 추가한다. R2 업로드에는 필수이며 local {}는 유지한다. 실제 원본 bytes와 대조하고 validating/ready 재전송도 기존 sha와 다른 값이면409다. R2의 412를 단순 성공으로 처리하지 않는다.
- SDK retry0, bounded read, 불명확한 저장 실패는 보존 결과를 확인한 뒤 동일 bytes만 수렴. 읽기/쓰기 장애는 일반 오류로 보고하고 사진 형식 오류로 영구 거부하지 않는다.
- R2 key prefix는 환경별로 고정하며 DB와 함께 유지한다. 기존 local 데이터의 자동 이관·운영 bucket 접근은 범위 밖이다. 현재 사용자 업로드가 있는 local QA는 보존하고 R2 검증은 별도 DB/prefix를 사용한다.
- R2 signed GET은 bearer capability다. 앱의 발급은 소유자만 가능하며 삭제 직후 새 URL 발급은 차단한다. 기존 URL은 최대 TTL 또는 실제 object 삭제까지 접근 가능하고 이 한계를 숨기지 않는다.
- attempt envelope도 R2에 보존하여 worker 로컬 cache 손실 후 원래 결과를 회수한다. envelope/파일 IO는 DB row lock 밖의 thread에서 수행한다.
- 실제 AI 호출·배포·BGM/HDR tone mapping은 포함하지 않는다.
- 사용자 실사진 정규화 문제를 독립 media Task로 병행한다. MPO 첫 JPEG 주프레임과 확인된 sRGB SDR transfer ICC를 가진 8bit HEIF 주이미지만 허용하며 HDR 보조 이미지를 적용하지 않는다. 일반 HDR/highbit/PQ/HLG는 계속 거부한다.

## Review Focus

1. 재시도412·동시 PUT·다른 bytes로 원본이 덮어써지거나 성공으로 오인되지 않는다.
2. 다른 사용자·삭제 페이지에 URL을 발급하지 않고 늦은 PUT/결과를 tombstone sweep으로 정리한다.
3. remote 장애/404/과대 파일·stream을 캐시 성공이나 영구 포맷 오류로 오인하지 않는다.
4. decoder·SDK IO가 event loop를 막지 않고 lease/fence·SIGTERM·원래 결과 복구를 유지한다.
5. 브라우저의 실제 CORS·signed Content-Length·필수 헤더를 확인하며 SDK 성공을 브라우저 성공으로 대체하지 않는다.
