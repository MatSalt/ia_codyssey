## 구현과 소비 인터페이스

`create_generation(session, owner_id, album_id, expected_version, key, request_hash, settings) -> (202, data)`와 `resume_generation(session, owner_id, album_id, run_id, expected_version, key, request_hash, settings) -> (202, data)`는 caller가 연 transaction만 사용한다. `generation_view(session, owner_id, album_id, run_id=None) -> GenerationView`는 owner/deleted 검사 후 최신 또는 지정 run을 읽으며 조회 중 album→run→task를 짧게 잠가 일관된 상태를 얻는다. `resume_failed_tasks(session,run_id)`의 기존 자체 transaction은 유지했고 HTTP는 이미 잠근 객체를 받는 `resume_locked_tasks(album,run,tasks)`를 사용한다.

POST `/api/v1/albums/{id}/generation` body `{expected_version}` 및 POST `/api/v1/albums/{id}/generation/resume` body `{run_id,expected_version}`는 CSRF·Origin·세션·Idempotency-Key가 필요하다. 성공 data는 `{run_id,status_url,album_version}`이며 status_url은 `/api/v1/albums/{id}/generation?run_id={run_id}`다. GET `/api/v1/albums/{id}/generation`은 선택 query run_id 외 입력을 받지 않는다. 성공/오류 envelope·no-store·새 request_id는 기존 HTTP 공통 경계를 사용한다.

소유권·삭제 검사를 먼저 수행하고 같은 key/hash는 version보다 앞서 이전 status/data를 재생한다. 새 접수는 최신 동의→모든 활성 page의 ready 업로드와 scoped source/normalized→수량/실제 원본 bytes→version→기존 run/상태·사용자 미완료 run 한도→로컬 설정을 검사한다. User 행 잠금이 같은 사용자의 서로 다른 album 접수를 직렬화한다. queued/running/action_required는 모두 미완료 한도를 점유하며 기존 성공 run도 새 생성할 수 없다. 새 run·3 task/page·queued task용 outbox·album processing/version/active_run_id·idempotency record는 한 transaction이다.

`run.input_snapshot`은 position 순 `{page_id:string, position:int, normalized_asset_id:string, sha256:string, input_is_3_4:bool}[]`다. sha256는 normalized bytes의 checksum이고 분기는 원본 방향 적용 후 저장된 input_is_3_4만 사용한다. 원본 입력·순서·설정은 run 이후 변경하지 않는다. Task2는 같은 normalized ID/sha를 caption과 image 입력으로 검증해 사용한다.

`run.config_snapshot`은 snapshot_version=1, execution_mode=local_fake, 공개 제한값, image_provider/caption_provider=local_fake, image_model=fake-canvas-v1, caption_model=fake-sentence-v1, prompt_version=local-fake-v1, target_ratio=3:4, 여섯 encoder 설정, max_attempts=3, attempt_budget=450, budget_scope=local_test_bound, estimated_cost=0, retry_backoff_seconds=[5,20], retry_jitter=true, sdk_max_retries=0, image/caption/media_concurrency=2/4/1, image/caption_timeout_seconds=300/60, lease/heartbeat_seconds=90/15를 보존한다. 이는 로컬 검증 전용 값이며 실제 비용 예산·운영 사용자 quota가 아니다. resume는 원래 run의 attempt_budget과 현재 task.attempt_count 총합에 재대기 수를 더해 검사하며 새 설정으로 snapshot을 바꾸지 않는다.

portrait task는 `stage=image_transform,status=succeeded,completion_kind=passthrough,output_asset_id=normalized_asset_id,requires_ai_call=false,has_persisted_input=true,attempt_count=0`이다. Task2 optimize는 이 output_asset_id를 읽으며 normalized를 result로 승격하거나 변경하지 않는다. portrait의 caption/optimize는 queued이고 각각 실행한다. 다른 image/caption은 requires_ai_call=true, optimize는 false이며 모든 입력은 보존 snapshot으로 연결된다. executor·runner·repository·미디어 실행을 이번 Task에서 연결하지 않았다.

GenerationView 공개 필드는 v1.3 그대로 `run_id,album_id,album_status,run_status,total_pages,completed_pages,failed_pages,unknown_pages,pending_pages,progress_percent,can_resume,poll_after_ms,pages[{page_id,tasks[{stage,status,completion_kind,error_code,retryable}]}]`다. 완료는 세 task 성공+scoped ready result/thumbnail+ai_caption/초기 caption_text 저장을 모두 확인한다. 완료→unknown→failed→pending으로 상호 배타 집계하고 정수 floor 진행률을 제공한다. action_required에 실행 중 task나 선행 image 성공 후 가능한 로컬 queued/retry_wait task가 없으면 polling null, succeeded/cancelled도 null이다.

resume는 safe_to_retry 실패만 재대기하며 unknown 혼합 시 requires_ai_call=false와 has_persisted_input=true를 모두 요구한다. 성공·unknown task와 attempt 수는 변경하지 않고 unknown의 최신 같은 attempt에 reconcile_attempt job을 멱등 예약한다. unknown이 없으면 album processing/run queued와 album version+1, 혼합이면 action_required와 현재 album version을 유지한다. retryable/can_resume은 같은 eligible policy와 남은 로컬 attempt budget을 사용한다.

내부 GET `/api/dev/config`는 `{dev_auth_enabled:boolean,dev_ai_enabled:boolean}`을 제공한다. DEV_AI_ENABLED는 기본 false이고 local에서만 true가 가능하며 test/production에서 true는 시작 설정 오류다. 비활성 접수·재개는 503 TEMPORARILY_UNAVAILABLE/retryable=false다. 공개 `/api/v1/client-config`의 값과 실제 모델 결정을 변경하지 않았다.
