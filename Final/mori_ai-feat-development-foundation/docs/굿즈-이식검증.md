# 굿즈 파일럿 선별 이식 — 2026-10-18

## 후속 실제 연동 작업

사용자 정책 확정 후 ui-components 격리 워크트리에서 저장·API·AI adapter·worker·제품 화면 연결을 구현했다. 아래 내용은 독립 이식 단계의 과거 검증 기록이다. 후속 상태는 [굿즈 연동 진행](굿즈-연동-진행.md) 및 [굿즈 계약 v1](굿즈-공통계약-v1.md)을 따른다. 실제 과금 호출·운영 배포 완료를 뜻하지 않는다.

## 독립 이식 단계 결과

전체 계획 중 **유저 플로우와 독립적인 기반 모듈**을 구현했다. 제품의 굿즈 생성·주문 흐름 전체가 완성된 상태는 아니다.

- 목업 렌더링, 외곽선·구멍 선택, 상품 예시25개 파일과 출처/hash.
- 공통 GlassButton·GlassPanel·PhotoFrame·ScreenHeader를 이용한 형태 선택·시안 이력·목업 검토 화면.
- 선택한 시안의 조상만 이어가는 분기 이력과 6개 디자인 프롬프트 프로필.
- 실제 API·DB·유료 호출과 분리된 `frontend/design-preview/goods.html` 검토 화면.
- 사용자 머지로 HEAD b853a65의 공통 UI가 합류했음을 확인했다. 이 세션은 다른 UI 브랜치를 merge하지 않았다.

## 실행한 검증

| 검증 | 명령/방법 | 결과 |

| 브라우저 실제 Canvas | 로컬 검토 페이지 | 키링/마그네틱 전환, 마그네틱 구멍 조절 없음, 키보드 연속 조절, 내부 탭 거부, 이미지 오류/복구 확인 |
| 반응형 | 실제 CSS viewport 320/390/426/430/1064px | 각 폭에서 document scrollWidth = innerWidth; 가로 넘침 없음 |

새 굿즈 프론트 검사18개는 Dockerfile frontend 단계에도 추가했다. 독립 검사 스크립트의 기본 이미지는 `mori-goods:baseline`; 없으면 frontend target을 해당 태그로 먼저 빌드하거나 `MORI_GOODS_FRONTEND_IMAGE=mori-goods:frontend`를 지정한다. 로컬 Node/Python에 패키지를 설치하지 않았다.

## 재현한 오류와 수정 근거

1. **키보드 구멍 선택 중 포커스 유실**: ready일 때만 slider를 렌더해 ArrowRight 직후 pending에서 slider가 제거됨. 브라우저에서 재현한 후 동일 원화의 geometry는 조절용으로 유지했다. export 가능한 결과는 여전히 pending 즉시 무효화된다. 연속 ArrowRight 뒤 slider active와 좌표 변경을 확인했다.
2. **중간 폭의 클릭 좌표 오차**: 700px 화면에서 canvas DOM이 618.18×540으로 나타나 object-fit 여백과 클릭 좌표가 달랐다. 높이 clamp를 제거하고 비율에 맞는 최대 너비를 적용했다. 수정 후 514.28×539.99, 800:840 비율을 확인했다.
3. **매우 긴 원화의 렌더 오류**: 20×400, 폭50mm에서 강조선 반지름이 -0.215가 되어 Canvas 오류 발생. 음수 반지름을 거부하는 Canvas 경계 테스트의 실패를 확인한 뒤 반지름을 0 이상으로 제한했다. renderer 검사2개 통과.

## 결정과 남은 제한

- Orca가 처음 `runtime_open_timeout`으로 연결되지 않아 현재 비-main checkout의 새 전용 경로에서 진행했다. 다른 세션의 배포 변경을 유지했고 별도 Run/Dispatch를 주장하지 않는다. 이후 사용자 UI 머지로 공통 부품을 사용할 수 있게 됐다.
- 플로우는 미정이라는 사용자 지시를 유지했다. 독립 모듈만 먼저 연결했으며, 정책을 임의 확정하면 관계/마이그레이션을 되돌려야 할 위험이 있어 HTTP·DB는 아직 변경하지 않았다.
- 실제 제조 가능성·구멍 강도·인쇄 품질을 검증한 결과가 아니다.
- Minor 보류: 구멍을 바꿀 때마다 원화 decode/외곽선 계산이 다시 실행된다. 최대16MP 검사만 두었고 실기기 메모리·지연은 측정하지 않았다. 실제 사용자 사진 연결 전에 모바일 측정과 원화별 geometry 캐시를 검토한다.
- 생성 worker·비용 장부·복구 통합, 굿즈 DB/API, 확정 주문, PDF·메일·운영자 제작함은 미구현이다. 이미지 생성 모델/비용 정책, 앨범 관계, 접수/변경 정책을 확정한 뒤 후속 단계로 진행한다.
- 기존 사진첩의 공개 HTTP 계약·DB schema 변경 없음. 실제 AI 호출·메일 발송·QA/운영 데이터 변경·배포·커밋·푸시 없음.
