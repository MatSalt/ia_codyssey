## 동작과 transaction

Task1의 `require_user → AuthContext(user_id, session_id)`, `require_csrf`, `request.app.state.session_factory`, `EmptyBody`, `APIError`, `envelope`를 그대로 사용한다. HTTP fixture와 개발 로그인 helper는 `test_auth_http.py`에서 재사용한다. API는 DB 접근 없이 service를 호출하며 repository가 SQLAlchemy DB 연산을 담당한다. service는 session을 받고 caller가 transaction을 소유한다.

`GET/POST /api/v1/albums`, `GET/DELETE /api/v1/albums/{album_id}`를 제공한다. 초안은 `{}`만 받고 제목 ‘나의 사진첩’·draft·version 1·서버 UTC 시각을 반환한다. list limit은 1~50/기본20이며 created_at DESC, id DESC keyset pagination을 base64url opaque cursor로 제공한다. 잘못된 cursor·UUID·버전·미지정 body/query 필드는 422다. 상세 DTO는 album/order_mode/pages/active_run_id 필드를 모두 제공한다. 사용자 응답의 no-store와 요청마다 새 request_id는 Task1 middleware를 사용한다.

초안 멱등 scope는 `owner_id + 'POST /api/v1/albums' + key`다. 자원별 후속 operation은 정규화한 대상 UUID를 포함한 method/path를 사용해야 한다. 동일 사용자의 User 행을 먼저 잠그고 key를 조회하므로 경쟁 insert가 unique constraint에 충돌하기 전에 직렬화된다. 서로 다른 키도 같은 사용자의 짧은 생성 transaction 동안 직렬화되며, 다른 사용자는 별개다. 동일 키는 하나의 album/idempotency row와 동일 HTTP status/data로 수렴하고 envelope의 request_id는 저장하지 않는다. replay 전에 album 소유권·삭제 상태를 잠금 조회하므로 삭제된 album은 동일 hash/다른 hash 모두 404다. 현재 version이 바뀌어도 저장된 생성 응답을 replay하며 다른 hash는 409 IDEMPOTENCY_CONFLICT다. 프로덕션 코드의 raw SQL 또는 unique exception HTTP 유출은 없다.

삭제는 album → run → task 순으로 잠그고 버전을 확인한다. stale 버전은 resource_type/resource_id/current_version을 담은 409 VERSION_CONFLICT다. 한 transaction에서 album=deleted·deleted_at·updated_at·version 증가·active_run_id 제거, 미완료 run 취소 및 finished_at 기록, task fence 증가·lease 제거·미완료 task 취소, album_cleanup outbox 한 개를 기록한다. page 잠금/파일 I/O는 필요하지 않아 수행하지 않는다. 삭제 뒤 조회·목록·재삭제·기존 생성 key 접근은 차단된다. 동시 삭제는 202 한 번과 404 한 번이며 outbox도 한 개다. 실제 파일 정리는 기존 outbox dispatcher가 연결하는 후속 Task3 cleanup handler의 범위다.

## Task3 인계와 한계

총괄의 현재 지시에 따라 `media_access`는 비어 있다. 현재 Task2가 생성하는 초안에는 페이지가 없고 cover=null/pages=[]이며 가짜 사진·더미 URL을 만들지 않는다. 기존/후속 업로드 페이지의 metadata 직렬화는 구현했지만 접근 URL adapter 연결은 Task3 이후 총괄이 편집 소유권을 조정한다.

연결 지점은 `service.summary(session, album)`의 cover, `service.get_album_detail(session, user_id, album_id)`의 source/result/thumbnail과 응답 media_access, `service.get_albums(session, user_id, cursor, limit)`의 items와 media_access다. `repository.ready_assets(session, album_id)`는 ready이고 deleted_at 없는 실제 asset만 반환하며 `service.media_ref(asset)`는 storage_key 없이 asset_id/mime/width/height만 직렬화한다. Task3는 여기서 현재 owner/album/page 연결과 역할을 재검증해 ready cover/thumbnail의 접근 URL을 발급하고, normalized 미리보기 허용 상태 및 원본 URL 금지를 유지해야 한다. 미완성 legacy seeded page의 nullable sort_date 등은 새로운 가짜 값으로 채우지 않는다; Task3 reservation/validation이 계약 필수값을 채워야 한다.

추가 agent를 사용하지 않고 작성자가 명세·락 순서·오류·필드·회귀를 자체 검토했다. 총괄 독립 검토·Git 통합·실제 브라우저·OAuth/R2/AI 연결·배포는 이번 작업에서 수행하지 않았다. 실제 외부 연동 성공으로 보고하지 않는다.
