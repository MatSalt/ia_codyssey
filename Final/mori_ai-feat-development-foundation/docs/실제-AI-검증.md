# 실제 AI 연결과 검증

2026-10-16. 사용자 승인 범위는 R2 업로드 확인, 비용 통제, 실제 글귀·이미지, 전체 화면 흐름, 실패 복구까지다. 배포는 포함하지 않는다.

## 실행 설정

- 실제 모드: `AI_REAL_CALLS_ENABLED=true`, `DEV_AI_ENABLED=false`.
- 글귀 `gpt-5.4-mini`, 이미지 `gpt-image-2`. 모델과 prompt/pricing profile은 run에 고정하고 지원하지 않는 조합은 미전송 상태에서 거절한다.
- 이미지 단일 입력·출력, 768×1024 WebP, medium. 정확히 세로 3:4인 원본은 이미지 호출을 생략한다. 글귀는 정규화 원본을 본다.
- SDK 자동 재시도 0. 글귀 timeout 60초, 이미지 timeout 300초. 응답을 확인하지 못한 유료 요청은 새 호출로 재시도하지 않는다.
- 현재 사용 가능한 누적 예산은 $5, 총 승인 상한은 $100이다. API key·로그인 정보·서명 URL은 문서나 Git에 기록하지 않는다.

## 비용 확인

서비스 컨테이너에서 다음 명령으로 현재 연결된 DB의 합계를 확인한다.

```sh
python -m backend.generation.budget_report
```

`confirmed_usage_cost_usd`는 공급자 usage에 검토한 단가를 적용한 산정액이다. 캐시 할인을 적용하지 않아 실제 청구액보다 높을 수 있다. `unconfirmed_reservations_usd`는 usage가 확정되지 않은 요청의 보유액이며 0원 사용으로 해석하지 않는다. 둘의 합계가 다음 호출의 허용 여부에 반영된다.

글귀당 $0.02, 이미지당 $1을 먼저 예약한다. 이미지 예약은 고정된 요청에 대한 보수적 추정액이며 공급자 청구액의 절대 상한을 보장하지 않는다. 실제 산정액이 예약보다 크면 초과분을 기록하고 추가 요청을 차단한다. 다른 프로젝트에서 같은 계정으로 발생한 비용은 이 원장의 범위 밖이다.

사진첩 삭제와 worker 재시작은 비용 원장을 지우지 않는다. DB 초기화, `docker compose down -v`, 원장 삭제를 예산 초기화 수단으로 사용하면 안 된다. 예산 부족은 현재 실행 한도와 누적 비용을 먼저 확인하고, 상한 확대는 승인된 총액 안에서만 한다.

## 복구 기준

- 전송 전 입력 오류: 외부 호출 없음, 안전한 실패 상태.
- timeout·취소·응답 유실: 예약 유지, unknown. 원래 저장된 결과만 복구.
- 정상 응답 후 DB 장애: 저장된 결과 봉투의 usage로 비용 정산을 재실행하며 공급자는 재호출하지 않음.
- 결과 수신 중 사진첩 삭제: 삭제 정책과 객체 정리를 적용하되 이미 발생한 비용은 유지.
- 서버 모드 변경: 과거 가짜 결과의 표시를 유지하고 대기 중인 다른 모드의 작업을 실제 AI로 실행하지 않음.

### 현재 로컬 서비스와 재시작

현재 서비스는 `http://127.0.0.1:8000`, Compose project `mori-r2-qa`다. 기존 QA DB/R2 namespace와 비용 원장을 보존하는 `.env.qa`를 로컬에 저장했다(권한600, Git 제외). 원래 `.env`는 수정하지 않았다. 실제 AI는 켜져 있고 개발 로그인·가짜 AI는 꺼져 있다.

```sh
docker compose --env-file .env.qa -p mori-r2-qa up --build -d --wait
docker compose --env-file .env.qa -p mori-r2-qa exec -T worker python -m backend.generation.budget_report
```

다른 project/DB로 기동하면 기존 사진첩과 비용 원장이 보이지 않으므로 위 명령을 사용한다. `.env.qa`는 비밀정보가 있으므로 공유하거나 Git에 추가하지 않는다. 재시작 시 `down -v`를 사용하지 않는다.

코드 출처: 기존 `moriai`에서 새로 이식한 코드 없음. 현재 `mori_ai`의 검증된 storage·fence·미디어 최적화 경로를 재사용했다. 계약은 v1.5로 갱신했고 생성 모드 응답과 샘플을 함께 수정했다. 배포와 외부 공개는 수행하지 않았다.


## 2026-10-16 성능·회상형 프롬프트 보완

새 생성의 글귀는 `openai-memory-v3`이며 기존 v1/v2 run의 동결 프롬프트는 보존한다. 이미지 모델·프롬프트·정확한 3:4 호출 생략 정책은 그대로다. 실제 실행은 이미지 2·글귀 4·최적화 1, 별도 검증 1 lane이며 생성 슬롯은 DB 전역 상한을 적용한다. [성능 검증 결과](성능-검증결과.md)를 참조한다.

합성 입력 글귀 2회 추가 산정액은 $0.0008505, 이미지 추가 호출 0회다. 비교 측정에 사용자 사진을 사용하지 않았으며 합성 전용 객체는 정리했다. 누적 비용은 실행 환경의 `budget_report`를 우선한다. 새 프롬프트의 실제 사진 톤은 사용자가 새 사진첩으로 확인할 항목이다.
