## 추가 발견: 새 앨범 브라우저 직접 업로드 CORS

사용자 테스트에서 18183 origin의 앨범 R2 직접 PUT이 preflight403으로 차단됐다. 이전 R2 검증은 서버 SDK 경유로 수행되어 브라우저 직접 업로드 CORS를 검증하지 못했다. 따라서 실제 R2 검증 성공을 새 앨범 브라우저 업로드까지 확대하지 않는다.

- 재현: Origin http://127.0.0.1:18183, PUT, Access-Control-Request-Headers content-type,if-none-match →403, Access-Control-Allow-Origin 없음.
- 이어진 complete422는 서버 로그에서 NoSuchKey / FileNotFoundError로 확인됐다. CORS 차단으로 객체가 없으므로 확인 요청이 실패한다.
- 앱용 R2 키의 get_bucket_cors는 AccessDenied. 원격 CORS를 변경하지 않았다.
- 콘솔용 추가 규칙: [18183 CORS JSON](storage/r2-cors.goods-local.json). 기존 운영/8000 규칙을 덮어쓰지 말고 배열에 규칙을 추가하거나 기존 동일 규칙의 AllowedOrigins에 새 origin만 추가한다.
- 설정 후 브라우저 preflight 및 직접 PUT→complete 검증이 남는다. /me401은 로그인 전 또는 포트 간 같은 호스트 cookie 교체로도 나타나므로 CORS와 구분한다. URL 없는 최초404의 대상은 미확정이다.
