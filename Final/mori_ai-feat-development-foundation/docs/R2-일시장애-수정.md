# R2 입력 일시장애의 안전 재개 수정

2026-10-16 · Task `task_5122a9b7ba13` · Dispatch `ctx_a0d2b8da7211`

## 원인과 수정 범위

`FakeExecutor._verify`의 `StorageUnavailable`은 일반 예외로 Runner에 도달했다. Runner는 `requires_ai_call`인 caption/image_transform의 일반 예외를 `unknown`, `safe_to_retry=false`, `accepted_or_unknown`으로 보존하므로, 결과를 만들기 전 입력 GET/HEAD 장애도 명시 resume으로 복구할 수 없었다.

`backend/generation/fake_adapter.py`의 execute 입력 검증과 image_transform의 source.path·변환 후 재검증 경계에서만 `StorageUnavailable`을 `FakeExecutionError('MEDIA_SAVE_FAILED', safe_to_retry=True)`로 변환했다. 기존 FakeExecutionError의 `dispatch_state='not_sent'`를 통해 Runner가 failed 상태와 안전 resume 근거를 기록한다. 로컬 fake 변환 직후 재검증 시점의 바이트는 아직 저장되지 않은 재생성 가능한 로컬 결과다.

`_verify` 자체 및 `recover_original`의 예외 동작은 유지했다. `_persist`와 원격 attempt envelope 저장은 새 예외 변환 범위 밖에 있으므로, 이미 결과가 저장되었을 가능성이 있는 장애를 not_sent로 되돌리지 않는다. 일반 입력 손상·누락의 재시도 정책도 변경하지 않았다.

## 회귀 테스트

`backend/tests/integration/test_r2_pipeline.py`에 실제 PostgreSQL·실제 Runner·실제 R2Storage·실제 resume HTTP를 사용하고 SDK 클라이언트만 모의한 10개 시나리오를 추가했다.

- caption 초기 GET/HEAD 장애 2개.
- image_transform 초기 GET/HEAD, 별도 source.path GET, 변환 후 재검증 GET/HEAD 장애 5개.
- 각 입력 장애에서 failed + MEDIA_SAVE_FAILED + safe_to_retry + not_sent 및 결과 미보존을 확인하고, 저장소 복구 후 resume을 거쳐 run succeeded·album review_ready·해당 attempt 2회까지 확인한다.
- caption/image_transform envelope PUT 또는 image_transform blob PUT이 원격 저장 후 응답 유실된 3개 시나리오에서 unknown/accepted_or_unknown을 유지하고, execute 재호출 없이 원본 복구·attempt 1회 유지를 확인한다.

실행 명령:

```sh
MORI_VERIFY_TEST_IMAGE=mori-ai:r2-tests ./scripts/verify-db.sh backend/tests/integration/test_r2_pipeline.py
```

RED: 수정 전 `7 failed, 26 passed in 24.76s`, exit 1. 새 입력 장애 7개 모두 expected failed / actual unknown으로 재현되었고, 저장 후 원본 복구 3개는 통과했다.

GREEN: 수정 후 같은 명령으로 `33 passed in 38.12s`, exit 0. PostgreSQL 17.11에서 migration upgrade/downgrade/upgrade 및 schema check가 통과했고, 생성한 임시 DB container·volume·network 정리를 확인했다. 기존 R2 원본 복구·캐시 재시작·입력 검증·이벤트 루프 비차단 검증도 함께 통과했다.

## 경계와 인계

공개 계약·DB migration 변경 없음. 기존 moriai 코드 이식 없음; 이 저장소 FakeExecutor와 R2 pipeline 검증을 수정했다. 실제 R2/AI·.env·QA volume·기존 서비스에 접근하지 않았다. 검증 스크립트는 `--env-file /dev/null`과 고유 Compose 프로젝트를 사용하며 자체 임시 DB/volume만 정리한다. 전체 통합 회귀 및 실제 R2 연결 판정은 총괄의 후속 검증 범위다.
