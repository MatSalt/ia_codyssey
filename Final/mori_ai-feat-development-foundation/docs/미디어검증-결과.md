# Task 2 미디어 경계·V02/V09 결과

2026-10-16, Asia/Seoul. 승인된 첫 개발 묶음 Task 2의 구현·합성 검증을 완료했다. **V02는 부분 검증이며 실제 iPhone HDR/광색역 색상 합격은 미판정**이다. V09는 아래 합성 RGB PNG 부하 조건에서 통과했으며 HEIC/HDR 최악 조건의 용량 확정을 뜻하지 않는다.

## 구현과 계약

- `normalize(source: bytes, filename: str) -> NormalizedImage`: 실파일 형식 검사(JPEG/PNG/WebP/HEIF), 20MiB·40MP 제한, EXIF 촬영일/offset 추출, 8방향 적용, alpha 유지, ICC→sRGB 변환, 무손실 WebP와 quality=80/480px 썸네일 생성. 원본 bytes와 SHA-256은 그대로 유지한다.
- 방향 적용 후 정확히 `width*4 == height*3`일 때만 AI 생략 표시를 반환한다. 정규화 축소는 크롭 없이 원래 정규화 픽셀에서 직접 수행하며 정확한 3:4는 3k×4k를 유지한다. bytes 상한 초과 시 긴 변을 0.8배씩 줄이고 1024px/작은 원본까지 실패하면 `IMAGE_NORMALIZATION_FAILED`다.
- Pillow-heif 1.8.1 plugin은 처음부터 primary index를 열고 컨테이너 변환을 적용하며 EXIF orientation을 초기화한다. 별도 보조 프레임 seek 없이 이 primary를 사용한다. HEIF 7방향과 PNG/JPEG EXIF 8방향 및 두 번째 primary를 실 codec으로 확인했다.
- 검증된 tone mapper가 없으므로 10bit/16bit·PQ/HLG·gain-map 힌트·HDR mastering/light 정보는 `IMAGE_NORMALIZATION_FAILED`로 거부한다. ICC 없는 비-sRGB nclx 색역/전달특성도 색상을 추정해 통과시키지 않는다. 이는 HDR 지원 완료를 뜻하지 않으며 실제 샘플 기반 추가 변환기가 남아 있다.
- `normalize_in_process`는 **async 함수이며 호출자는 `await`한다**. 동기 정규화를 event loop에서 호출하지 않도록 이 경계를 채택했다. 임시 파생본 디렉터리 정리, timeout kill/reap, cancellation kill/reap, 20ms 간격 Linux `/proc` RSS 감시(512MiB 시작 예산)를 담당한다. RSS 감시는 순간 peak의 엄격한 커널 제한을 대체하지 않으며 검증 container에는 별도 1GiB/동일 swap 한도를 적용했다.
- 프로세스 내부 오류 코드는 `IMAGE_PROCESS_TIMEOUT`, `IMAGE_PROCESS_MEMORY_LIMIT`이고 이후 upload application에서 공개 오류/재시도 정책과 연결해야 한다. worker 실행 슬롯 1과 DB/storage 연결은 이 Task에서 구현하지 않았다.
- 계약 문서·공통 DTO·DB·worker·의존성·Makefile·Git index/commit/branch 변경 없음. 기존 서비스 코드는 재사용하지 않았으며 전부 신규 구현이다.

## 미실행·실패와 후속

- 실제 사용자 소유 iPhone HEIC/10bit/PQ/HLG/gain-map 및 참조 SDR 사진을 받지 않았으므로 실제 HDR tone mapping, 밝기·중간톤·피부색·하이라이트 육안 검사는 **미실행**이다. 8bit 합성 HEIF 통과를 HDR 합격으로 보고하지 않는다.
- ICC 엔진은 합성 sRGB profile로 실행했고 손상 profile 거부를 확인했다. 실제 Display P3/광색역 참조 색상 비교는 **미실행**이다. 적절한 ICC 없는 nclx 광색역은 현재 명시적 변환 실패다.
- 40MP RGBA/고엔트로피/HEIC/HDR 최악 부하·20MiB 상한 부근 실제 사진 부하는 **미실행**이다. 이번 합성 단색 PNG 결과만으로 배포 크기를 확정할 수 없다.
- 실제 샘플 권한 확보 후 libheif SDR rendition 의미를 확인하고, 필요하면 libvips/FFmpeg 등의 HEIF/transfer 지원을 실제 검증해 하나를 추가 요청해야 한다. 추가 도구/의존성은 설치하지 않았다.
- source 수량 1~50·album 총합 300MiB·소유권·보관/결과 quality=90·AI 출력 WebP 재사용은 upload/application/optimize 후속 경계다. normalized 무손실 WebP 입력도 재인코딩 가능하며 bytes 재사용 최적화는 의무가 아니므로 추가하지 않았다.
- 독립 agent 리뷰는 사용자 지시로 실행하지 않았으며 구현자 자체 검토 후 총괄 리뷰를 요청한다. full suite 통과를 PostgreSQL V03/V04나 실제 AI/OAuth/storage 성공으로 대체하지 않는다.

## 총괄 통합 보완

codec 사전 검사 실패가 뒤 pytest 성공으로 가려지는 것을 exit 7→0으로 재현했고, container shell을 sh -ec로 변경했다. 테스트 image override 불일치도 실패를 재현한 뒤 MORI_VERIFY_TEST_IMAGE 우선·MORI_VERIFY_IMAGE runtime base 뒤 -tests 규칙으로 통일했다. 회귀 검증은 backend/tests/test_verification_scripts.py에 추가했다.

깨끗한 빌드 중 취소 테스트가 PID 파일 생성 직후 빈 내용을 읽는 race를 재현했다. 파일 존재뿐 아니라 숫자 내용까지 준비된 뒤 PID를 보존하고 취소하도록 테스트 동기화를 수정했다. 실제 설치 재검증 67 passed/DB 26 skipped, 실제 DB 연결 전체 93 passed로 확인했다.
