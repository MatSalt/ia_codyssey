# 굿즈 실제 연동 진행

기준: 굿즈 이식 계획 10~11절, 사용자 구현 승인.

- [x] 저장 모델·API·임시 작업 폐기·완성 목록·앨범 연결
- [x] 이미지 AI adapter·worker·비용 기록·모델 교체
- [x] 앱 진입·프로필·디자이너·이탈 보호·내 디자인
- [x] 격리 검증·전체 회귀·독립 리뷰

Ruling: 제작 주문 접수/PDF/메일은 이번 저장·API·AI 연결 범위 밖이다. 연결 잠금 상태와 서버 검증을 제공하고 실제 주문 시작 전이는 후속 주문 계약에서 연결한다.
Ruling: 사용자 작업 복원은 제공하지 않으며 임시 서버 실행 상태는 24시간 만료 및 명시적 폐기로 정리한다. 완성 기록과 비용 기록은 보존한다.

## 진행 근거

- 저장/소유권/완성 멱등성/앨범잠금 API 검사: 신규 API 부재로 RED 확인 후 초기2검사 GREEN.
- 사진 교체 검사: helper 부재 RED 후 구현. 최초 실패 재시도·새 방문 키·공유 이미지 슬롯은 독립 리뷰의 Important3건으로 재현 검사 추가.
- 기존 굿즈 기반은 root에서 복사하여 원본 세션 작업을 보존했다. 수정 위치는 ui-components 격리 워크트리다.
- Ruling: 새 앨범은 기존 생성 흐름을 유지하고 완성 후 디자인 상세로 돌아와 명시적으로 연결한다. 연결 전 굿즈는 이미 저장돼 있다. 자동 연결을 기대하는 경우 후속 UX 조정이 필요하다.
- Ruling: 고리 범위 검사와 디자인 저장은 제조 승인과 다르며 제작 형상 검증은 주문 단계에서 수행한다.
- 독립 리뷰: 실패 시안 부모 선택, 공유 슬롯, 동일 경로 초기화3건 수정 및 회귀 검증 완료. 낮은 우선순위 Compose quota 전달도 함께 반영했다.

- 전체 회귀의 worker scheduler 격리 검사4건은 asyncio.Event를 하나의 stopped로 치환한 fixture가 새 goods DB lane 내부 이벤트까지 치환해 조기 종료했다. 새 lane을 테스트 stub으로 격리하고 기존 스케줄링 assertions를 유지했다. goods 실제 DB lane은 별도 통합 검사로 검증한다.

## 실제 로컬 앱 검증

- 전용 runtime http://127.0.0.1:18181/goods. 개발 alpha 계정, fake AI, 독립 DB/media. 원본 QA/운영 미변경.
- fixture JPG1장 → 실제 API 업로드/worker 가짜 시안 → 고리 미리보기 → 디자인 완성 저장 → 기존 테스트2장 앨범 연결 확인.
- 새 앨범 생성 후 사진 선택 화면과 ‘앨범 완성 후 디자인으로 돌아가 연결하기’ 안내 확인. 디자인 저장이 유지된다.
- 최종 빌드의 같은 /goods 메뉴 이탈: 취소 시 선택1개 유지, 확인 시 선택0개·모양 선택 첫 화면 초기화 확인. 테스트 확인창 override는 검증 후 원복했다.
- 프론트 전체103개 및 TypeScript/Vite/runtime 빌드 통과. 초기 전체 backend run에서 scheduler fixture4건과 부하 중 미디어 타이밍1건 실패를 관찰했다. scheduler fixture는 새 DB lane 격리를 반영했다. 최종 native ARM64 전체 재검증은 859 passed / 0 failed / 1 warning (374.90초)다. migration up/down/up 및 schema check도 통과했다. warning은 기존 Starlette의 AnyIO BlockingPortal deprecation이다.
- 실제 유료 AI·운영 OAuth/R2·실기기 검증은 실행하지 않았다. SDK 경계는 injected client로 검증했으며 실제 투명도·인물보존 품질 검증과 구분한다.

## 최종 검증 및 인계

- 실제 호스트 아키텍처 ARM64 검증 image로 `MORI_VERIFY_TEST_IMAGE=mori-goods-connect:verify bash /tmp/mori-goods-verify-native.sh backend/tests` 실행: 859 passed. 임시 스크립트는 기존 verify-db.sh의 격리 실행 절차를 유지하고 테스트 image platform만 ARM64로 맞췄다.
- AMD64 에뮬레이션 및 병렬 빌드 부하 중 heartbeat/동시 실행 peak 타이밍 실패를 관찰했으며, 해당 제품 로직이나 assertion을 완화하지 않았다. 최종 전체 실행에서는 두 검사 모두 통과했다.
- frontend 103 passed, TypeScript/Vite/runtime build 성공, `git diff --check` 통과.
- 로컬 앱에는 최종 runtime을 반영했다. 별도 DB/media, 개발 로그인·가짜 AI 환경이다. 페이지 새 진입 후 내 디자인 목록 및 가짜 AI 표시, 저장된 앨범 연결 유지 확인.
- 실제 유료 AI 호출, 운영 데이터 migration, merge/push/배포는 수행하지 않았다. 제작 주문 시작 API·PDF·메일 및 제조 품질 승인은 후속 범위다.
- 변경: backend goods 모델/migration/API/provider/worker, 사진첩과 공유 이미지 슬롯, frontend goods 흐름/내 디자인/프로필, 환경 설정 및 공통계약·샘플·검증 기록. 기존 굿즈 baseline의 출처는 재사용조사·굿즈 이식검증 문서에 유지했다.

## 후속 실제 연동 검증 완료

사용자 승인으로 UI 검토·실제 R2/OpenAI 검증을 수행했다. gpt-image-2 투명 배경 거절을 확인한 뒤 사용자 결정에 따라 굿즈만 gpt-image-2.5-sunburst로 변경했다. 실제 생성·수정2회, 저장·재조회·재시작·소유권 검증 통과. 산정 비용$0.053351. 위의 ‘실제 호출 미실행’은 직전 구현 완료 시점 기록이며 최신 결과는 [굿즈 실제 연동 검증](굿즈-실제연동-검증.md)을 따른다. 통합·배포는 미실행이다.
