## 1. 목적과 범위

사용자가 사진을 간편하게 넣으면 AI가 이미지를 분석하여 페이지별 한 문장의 글귀를 생성하고, 사용자가 이를 직접 수정하여 사진첩을 만드는 서비스다. 사진 1장당 1페이지로 구성하고 사용자가 정한 순서를 유지한다. 사진첩은 모바일에서 사진 감상을 방해하지 않는 UI로 제공한다. 굿즈는 아래 별도 미확정 최소안으로만 검토한다.

현재 서비스의 핵심 기능은 사진첩 제작, 뷰어, 책장이다. 굿즈 디자인·미리보기는 전체 미확정이며 기본 예시 키링·내 이미지 기반 AI 키링 이미지 생성·주문하기 버튼의 최소안으로 검토한다. NFC 굿즈를 통한 사진첩 접근 제한은 보안 목표로 검토하며 구현 방식은 미정이다. 기존 `moriai`의 필요한 모듈을 선별 재사용하고, 뷰어는 별도로 제공된 추억책 UI를 참고한다. 기존 운영 서비스의 데이터·자격증명·인프라와 분리한다.

### 요구사항 표기

- **확정**: 사용자가 직접 지정한 요구사항.
- **제안**: 사용 흐름의 완결성과 안정성을 위해 검토할 요구사항. 구현 확정 사항이 아니다.
- **과제 필수**: 과제 원문에서 요구하는 항목. 구체적인 구현 방법은 별도 설계한다.
- **미정**: 추가 결정이 필요한 정책 또는 범위.
- **미확정 / 향후 확장 검토**: 현재 구현 범위에 포함하지 않으며, 추후 도입 여부를 검토하는 기능.

## 2. 기본 사용자 흐름

- 굿즈 흐름(전체 미확정): 기본 예시 키링 이미지 → 내 이미지 업로드 → 생성형 AI 키링 이미지 확인 → 주문하기 버튼. 버튼 이후 흐름은 미정이다.
- 사진첩 제작 흐름: 내 책장 → 사진 간편 첨부 → 날짜순 기본 정렬·사용자 순서 변경 → 이미지 분석·페이지별 한 문장 생성 및 AI 3:4 조정 → 글귀 확인·직접 수정 → 완성된 사진첩 관리. 처리 단계의 실행 순서는 상세 설계에서 정한다.
- 감상 흐름: 사진첩 열기 → 사진첩 감상. NFC 굿즈 태깅·접근 검증은 전체 미확정인 별도 검토안이다.

구글·카카오 로그인을 제공하고 로그인한 소유자가 자신의 사진첩을 제작·조회·감상한다. 서버 세션·CSRF는 공통계약을 따르며 세션 수명·실패 처리는 검증계획의 D01~D02에서 구체화한다.

#### AI 이미지 변환 정책

확정된 원칙은 다음과 같다.

- 모든 첨부 사진의 결과 비율은 세로 3:4다. 방향 적용 후 원본이 정확한 해당 비율이면 AI 확장을 생략하고 WebP 정규화·글귀 분석·표시 최적화는 수행한다.
- 크롭이 아니라 생성형 AI를 활용하여 자연스럽게 변환한다.
- 그림체 선택은 초기 범위에서 제외하며 원본 사진의 실사 느낌을 유지한다.

2026-10-17 사용자 결정으로 원본 파일 별도 보존과 무손실 정규화 의무를 해제했다. 서비스에 충분한 품질의 비율 유지 축소·손실 WebP를 허용하며 정규화본·AI 결과·썸네일을 구분한다. 2026-10-18 전처리·정규화·임시 source 정리 구현과 검증은 공통계약 v1.6 및 미디어 전처리 검증 기록을 따른다. 주요 인물·사물 보존과 부족한 배경의 자연스러운 확장을 목표로 하며 GPT Image 2의 변환 품질은 사용자가 확인했다. 실제 배포 입력의 색상·HDR·오류·비용 검증은 검증계획에서 수행한다. 그림체 변환은 향후 기능 채택 시 설계한다.

가로 화면의 펼친 책 UI, 읽던 위치 저장, 일반 링크 공유는 미정이다. NFC 진입은 보안 검토 범위에 포함하며 영상 첨부·편집·재생과 자동 분류·선별은 미확정인 향후 확장 후보로서 현재 구현 범위에 포함하지 않는다.

아래는 최대한 단순한 형태로 검토하는 최소안이다. 세 항목 모두 아직 확정 요구사항이 아니며, 도입 여부를 결정한 후 구현 범위에 포함한다.

|---|---|---|---|
| GDS-01 | 기본 예시 키링 | 기본 예시 키링 이미지를 보여준다. | 미확정 / 최소안 검토 |

### 3.5 NFC 접근 보안 검토 — 전체 미확정

이 절의 모든 항목은 검토 자료이며 현재 확정 구현·인수 범위에 포함하지 않는다.

**사용자 목표:** 실물 NFC 굿즈를 통해서만 사진첩을 열고 복사·공유된 외부 링크만으로는 볼 수 없도록 할 수 있는지 검토한다. 이 목표의 달성 수준과 기술 방식은 아직 확정하지 않았다.

| ID | 기능 | 요구사항 | 상태 |
|---|---|---|---|
| SEC-01 | NFC 인증 진입 | NFC 검증을 통과한 경우에만 감상 세션을 발급하는 방식을 검토한다. 태그 종류·등록·키 설정·서버 검증 방법을 먼저 검증한다. | 미확정 / 검토 |
| SEC-02 | 외부 링크 접근 제한 | 인증 세션이 없는 브라우저는 사진첩 주소만으로 콘텐츠를 조회할 수 없도록 한다. NFC 인증값이 포함된 링크의 최초 사용 전 전달 문제는 별도로 평가한다. | 미확정 / 검토 |
| SEC-03 | 재사용 제한 | 보안 태그의 인증값과 카운터를 검증하고 이미 소비한 인증 요청의 재사용을 차단한다. 만료·동시 요청·기기별 재방문 정책은 미정이다. | 미확정 / 검토 |
| SEC-04 | 미디어 보호 | 페이지뿐 아니라 이미지·영상 API와 파일 접근에도 권한 검사를 적용한다. 공개 고정 미디어 URL로 우회하지 못하도록 하며 만료 URL을 쓰면 유효기간 내 공유 가능성도 평가한다. | 미확정 / 검토 |
| SEC-05 | 분실·폐기 처리 | 분실한 굿즈의 접근 권한을 해제하고 필요하면 새 굿즈로 연결을 이전하는 기능을 검토한다. | 미확정 / 검토 |
| SEC-06 | 제작자 접근 정책 | 제작자가 책장에서 자신의 사진첩을 편집·미리보기·감상할 수 있는 범위와 NFC 인증 예외를 정의한다. | 미확정 / 검토 |

#### 기술적 가능 범위

- **고정 URL을 담은 일반 NFC 태그:** 서버가 같은 URL의 태깅 접속과 복사 링크 접속을 신뢰성 있게 구별할 수 없으므로 실물 전용 접근 보장을 충족하지 못한다. 숨긴 URL이나 진입 경로 표시는 실물 소지 증명이 아니다.
- **보안 NFC 태그 + 서버 검증:** NXP NTAG 424 DNA 같은 태그는 읽기마다 암호학적 인증 메시지를 포함한 URL을 제공할 수 있다. 태그별 키 설정, 서버 검증, 카운터 재사용 차단, 제한된 감상 세션을 조합하는 설계를 검토한다. 특정 제품 채택을 확정한 것은 아니다.
- **남는 한계:** 인증 링크가 처음 사용되기 전에 전달되는 경우, 실시간 중계, 유효 세션 공유, 화면 캡처·이미 다운로드한 콘텐츠 복제까지 완전히 차단한다고 보장하지 않는다. 태깅 순간의 인증과 감상 내내 실물을 소지하는 것은 다른 조건이다.
- **브라우저 호환성:** 웹 NFC API는 지원 범위가 제한적이므로 모바일 운영체제의 NFC URL 열기와 브라우저 내 NFC 읽기를 구분한다. 실제 iPhone·Android에서 선택한 방식의 동작을 검증한다.

근거: [NXP NTAG 424 DNA 제품 문서](https://www.nxp.com/products/rfid-nfc/nfc-hf/ntag-for-tags-and-labels/ntag-424-dna-424-dna-tagtamper-advanced-security-and-privacy-for-trusted-iot-applications:NTAG424DNA), [NXP SUN 인증 메시지 설명](https://www.nxp.com.cn/docs/en/brochure/NTAG424_BROCHURE.pdf), [MDN Web NFC API](https://developer.mozilla.org/en-US/docs/Web/API/Web_NFC_API). 위 서버 정책과 한계는 문서의 태그 기능을 바탕으로 한 설계 검토 사항이다.

- v1.1 (2026-10-16): 중복 검증 목록을 검증계획으로 통합하고 현재 계약의 HEIF/HEIC·WebP·빈 글귀·완료/수정·소유자 감상 기준을 반영. 기능 ID와 초기/향후 범위 유지.
- v1.0 이하의 변경 이력과 교육장 AI API 검토 기록은 [통합 전 명세](docs/archive/2026-10-16/기능요구명세서.md)에 보존한다. 교육장 API는 필수 의존성이 아니다.

## 2026-10-18 굿즈 확장 승인과 실행 범위

사용자가 파일럿의 굿즈 목업·외곽선·구멍 선택, 디자인 프롬프트·예시, 대화형 생성·시안 이력, 제작 접수·PDF·메일·운영자 제작함의 선별 이식과 공통 UI 기반 리디자인 계획 실행을 승인했다. 앞부분의 굿즈 전체 미확정 표기는 이 승인 이전의 사진첩 초기 범위 기록이다. 유저 플로우 중 진입·앨범 연결·사진 교체 규칙은 아래 후속 결정으로 확정했다. 나머지 세부 정책은 미정이며 기존 사진첩의 공유·NFC·스타일 정책을 자동 변경하지 않는다.

현재는 독립 목업·예시·표현 컴포넌트와 프롬프트/분기 순수 로직을 구현했다. 생성·주문 API 전체 완료를 뜻하지 않는다. [이식 계획](docs/superpowers/plans/2026-10-18-goods-pilot-import.md)과 [검증 결과](docs/굿즈-이식검증.md)를 따른다.

### 굿즈 사용자 흐름 후속 확정 (2026-10-18)

- 로그인 후 굿즈 만들기로 진입하며 상단 프로필 메뉴에 굿즈 만들기·내 디자인·내 책장·로그아웃을 제공한다.
- 굿즈 완성 후 앨범 연결하기에서 기존 완성 앨범 선택 또는 새 앨범 만들기를 제공한다.
- 입력 사진은 1장이다. 다른 사진으로 교체할 때 현재 사진·생성 시안·대화 내역·고리 위치 초기화를 경고하고 확인받는다.
- 취소·새 사진 검증 실패 시 기존 작업을 유지한다. 확인 및 새 사진 검증 성공 후 초기화한다.
- 이미 완성해 저장한 굿즈와 연결된 사진첩은 삭제하지 않는다.
- 세부 경고 문구·검증 조건·남은 결정은 [굿즈 계획 10절](docs/superpowers/plans/2026-10-18-goods-pilot-import.md#10-사용자-확정--굿즈-진입앨범-연결사진-교체)을 따른다. 이 기록은 구현 완료를 의미하지 않는다.

### 굿즈 저장·생성·연결 정책 후속 확정

- 굿즈 생성 참고 사진은 기기에서 새로 1장 업로드하며 모든 형태에서 필수다.
- 작업 중 저장·재접속 복원은 제공하지 않는다. 작업 화면 이탈 시 폐기 경고를 표시하고 확인하면 작업을 지운다. 취소 시 유지한다.
- 요청당 시안 1개를 생성한다. 수정 시 새 시안을 추가하며 작업 안에서 이전 시안을 선택할 수 있다.
- 생성 횟수·사용자 비용 제한은 현재 미적용이며 추후 반드시 도입한다. 비용 계측은 유지한다. 실제 개발 검증의 기존 승인 예산과는 구분한다.
- 실제 계정의 투명 배경 미지원 확인 후 사용자 승인으로 굿즈 기본 모델은 `gpt-image-2.5-sunburst`를 사용한다. 사진첩 `gpt-image-2`는 유지하며 굿즈 모델은 설정/adapter로 교체할 수 있다.
- 디자인 완성 시 저장하고 프로필의 **내 디자인**에서 완성 목록을 제공한다. 앨범 연결은 완료 조건이 아닌 별도 단계다.
- 굿즈당 앨범 1개를 연결한다. 제작 요청 시작 전 변경 가능하며 시작 후 다른 앨범으로 변경 불가다.
- 앞선 계획의 자동 저장·사진 없는 생성·6회 제한 제안은 채택하지 않는다. 상세 기준은 굿즈 계획 11절을 따른다.
