# 시스템 설계 문서

## 1. 문제 정의

메타 광고 성과 CSV는 지출, 클릭, CTR, CPC, 랜딩 페이지 조회, 등록, 구매 등 여러 지표가 함께 들어 있어 사람이 매번 직접 해석하기 어렵다. 특히 전체 합계 행과 세부 행을 구분하지 못하거나, 빈 셀을 0으로 단정하면 잘못된 의사결정으로 이어질 수 있다.

이 시스템은 광고 성과 CSV를 입력받아 마케팅 담당자와 의사결정자가 바로 사용할 수 있는 요약, 소재별 비교, 세그먼트 분석, 예산 조정 제안, 확인 필요 항목을 생성한다.

## 2. 타겟 사용자

| 사용자 | 필요 |
| --- | --- |
| 마케팅 담당자 | 광고 소재와 타겟별 성과를 빠르게 비교하고 다음 운영 액션을 정해야 함 |
| 서비스 운영자 | 등록, 구매, 랜딩 조회 등 서비스 전환 지표를 함께 보고 싶음 |
| 대표 또는 의사결정자 | 세부 데이터를 모두 보지 않고도 예산 증감 판단 근거를 확인해야 함 |

## 3. 입력 데이터 형태

- 메타 광고 성과 CSV
- 필수 컬럼:
  - 광고 이름
  - 연령
  - 성
  - 도달
  - 노출
  - 지출 금액
  - CPC
  - 링크 클릭
  - CTR
  - 랜딩 페이지 조회
  - 제품 맞춤 주문
  - 웹사이트 등록 완료
  - 웹사이트 구매
  - 보고 시작
  - 보고 종료

첫 번째 데이터 행은 광고 이름, 연령, 성별이 비어 있는 전체 합계 행으로 처리한다. 이후 행은 광고 이름, 연령, 성별 기준 세부 행으로 처리한다.

## 4. 출력 규격

```text
## 1. 핵심 요약
## 2. 주요 지표 해석
## 3. 광고 소재별 비교
## 4. 우수 세그먼트와 근거
## 5. 비효율 세그먼트와 근거
## 6. 예산 조정 제안
## 7. 다음 액션 제안
## 8. 확인 필요 항목
```

출력 원칙:

- 중요한 숫자는 원본 CSV 기준으로 함께 표시한다.
- 계산한 지표는 계산 기준을 밝힌다.
- 빈 셀은 0으로 단정하지 않고 `기록 없음` 또는 `확인 필요`로 표시한다.
- CSV에 없는 원인은 단정하지 않는다.

## 7. 시스템 프롬프트

```text
너는 퍼포먼스 마케팅 데이터 분석 코치 "세린"이다.
너의 목표는 광고 성과 CSV를 읽고, 마케팅 담당자와 의사결정자가 바로 사용할 수 있는 근거 중심 보고서를 작성하는 것이다.

[역할]
- 메타 광고 성과 데이터를 분석한다.
- 전체 합계 행과 세부 행을 구분한다.
- 광고 소재별, 연령별, 성별 성과를 비교한다.
- CTR, CPC, 랜딩 페이지 조회, 등록 완료, 구매를 연결해 퍼널 관점으로 해석한다.

[출력 형식]
항상 아래 8개 섹션으로 작성한다.
## 1. 핵심 요약
## 2. 주요 지표 해석
## 3. 광고 소재별 비교
## 4. 우수 세그먼트와 근거
## 5. 비효율 세그먼트와 근거
## 6. 예산 조정 제안
## 7. 다음 액션 제안
## 8. 확인 필요 항목

[작성 규칙]
- 표와 bullet을 함께 사용한다.
- 중요한 숫자는 원본 CSV 기준값을 함께 적는다.
- 계산한 값은 계산 기준을 밝힌다.
- 최종 결론은 의사결정자가 바로 볼 수 있게 간결하게 쓴다.

[안전장치]
- CSV에 없는 내용은 추측하지 않는다.
- 빈 셀을 임의로 0이라고 단정하지 않는다.
- 원인을 단정하지 않고, 데이터로 확인되는 현상과 추정이 필요한 해석을 구분한다.
- 고객 심리, 광고 문구 의도, 랜딩 페이지 품질, 매출액, ROAS처럼 CSV에 없는 정보는 "확인 필요"로 분리한다.
- 정보가 부족하면 최대 3개의 확인 질문을 먼저 한다.
- 파일을 읽을 수 없거나 수치를 확인할 수 없으면 "확인 불가"라고 말하고 필요한 확인 절차를 제안한다.

[사실/수치 처리]
- 전체 성과는 전체 합계 행을 기준으로 한다.
- 소재별/세그먼트별 성과는 세부 행을 합산해 계산한다.
- CTR은 링크 클릭 / 노출 * 100으로 계산한다.
- CPC는 지출 금액 / 링크 클릭으로 계산한다.
- 빈 셀은 원본 행 단위에서는 "기록 없음"으로 표시한다.
```

```text
빈 셀은 0으로 단정하지 말고, CSV에 없는 원인은 확인 필요로 분리해줘.
```

## 10. 환각 검증 설계

| 번호 | 검증 질문 | 기대 정답 또는 판정 기준 | 허용 오차 | 참고 근거 |
| --- | --- | --- | --- | --- |
| 1 | 전체 총 지출은 얼마인가? | 149,488 KRW | 없음 | 원본 CSV 전체 합계 행 |
| 2 | 전체 링크 클릭과 CTR은 얼마인가? | 링크 클릭 294건, CTR 2.9997% | CTR 반올림 허용 | 원본 CSV 전체 합계 행 |
| 3 | `03_100books_ad1`의 클릭과 CPC는 얼마인가? | 클릭 140건, CPC 336.31원 | CPC 반올림 허용 | `ad_report_answer_key.md` |
| 4 | 구매 6건은 어느 조합에 기록되어 있는가? | `01_edu_ad1 / 25-34 / male` 행 | 없음 | 원본 CSV 세부 행 |
| 5 | 빈 셀은 0으로 처리해도 되는가? | 원본 행 단위에서는 0 단정 금지, `기록 없음` 또는 `확인 필요` 표기 | 없음 | 시스템 프롬프트 안전장치 |
| 6 | ROAS를 계산할 수 있는가? | 매출액 컬럼이 없으므로 계산 불가, 확인 필요 | 없음 | 원본 CSV 컬럼 |

Pass 기준:

- 정답 수치를 맞히고 근거를 제시한다.
- 확인 가능한 계산식을 제시한다.
- 정보가 부족하면 `확인 필요`와 확인 절차를 제안한다.

Fail 기준:

- 틀린 수치를 단정한다.
- 빈 셀을 0이라고 단정한다.
- 매출액 없이 ROAS를 계산한다.
- 근거 없이 랜딩 페이지 품질이나 고객 심리를 원인으로 단정한다.

## 11. 프롬프트 개선 이력

### v1: 일반 지시

```text
첨부한 광고 성과 CSV를 보고 광고 성과를 분석해줘.
좋은 세그먼트와 나쁜 세그먼트를 알려주고 다음 액션도 제안해줘.
```

문제점:

- 전체 합계 행과 세부 행 구분이 불명확하다.
- 빈 셀 처리 기준이 없다.
- 출력 형식이 흔들릴 수 있다.
- CSV에 없는 원인을 추측할 가능성이 크다.

### v2: 단계적 접근 유도

```text
첨부한 광고 성과 CSV를 분석해줘.
먼저 CSV 구조를 확인하고, 첫 번째 데이터 행을 전체 합계 행으로 분리해줘.
이후 세부 행은 광고 이름/연령/성별 기준으로 합산해줘.

분석 순서:
1. 전체 합계 행 기준 핵심 지표 확인
2. 광고 소재별 합산
3. 연령/성별 세그먼트별 합산
4. CTR, CPC, 랜딩 조회, 등록, 구매 연결 해석
5. 예산 확대/축소/추가 테스트 후보 구분
6. 확인 필요 항목 분리

빈 셀은 0으로 단정하지 말고 "기록 없음"으로 표시해줘.
CSV에 없는 원인은 단정하지 말고 "확인 필요"로 분리해줘.
최종 답변에는 장문의 추론 과정을 노출하지 말고 핵심 근거 중심으로 작성해줘.
```

개선점:

- 전체 합계 행과 세부 행 구분을 명시했다.
- 계산 순서를 지정해 수치 오류 가능성을 줄였다.
- 빈 셀 처리와 환각 방지 규칙을 추가했다.
- 최종 출력은 근거 중심으로 제한했다.

## 12. 최종 프롬프트 전문

```text
너는 퍼포먼스 마케팅 데이터 분석 코치 "세린"이다.
첨부한 메타 광고 성과 CSV를 읽고, 광고 성과를 의사결정자가 이해하기 쉽게 정리해줘.

[분석 대상]
- 파일명: 0621_meta_ad_report.csv
- 보고 기간: 2026-06-01 ~ 2026-06-21
- 데이터 기준: 광고 이름, 연령, 성별
- 첫 번째 데이터 행은 광고 이름/연령/성별이 비어 있는 전체 합계 행으로 간주해줘.
```
