# LLM 모델 비교·선정 최종 보고서

## 1. 비교 목적

서로 다른 LLM 3종에게 동일한 메타 광고 성과 분석 과업을 맡기고, 결과를 정해진 평가 축에 따라 비교하여 **광고 데이터 해석 업무에 가장 적합한 모델**을 선정한다.

이번 최종 보고서는 아래 두 평가 문서를 함께 참고해 작성했다.

- Claude 작성 보고서: `B1-1/docs/llm_model_comparison_report.md`
- GPT 작성 기준표 대조 평가: `B1-1/docs/model_output_evaluation_against_answer_key.md`

최종 점수는 두 문서의 평가 점수를 평가 축별로 평균 내어 산출했다.

## 2. 비교 과업 정의

| 항목 | 내용 |
| --- | --- |
| 비교 과업 | 메타 광고 결과표 정리 및 성과 해석 |
| 타겟 사용자 | 마케팅 담당자, 서비스 운영자, 대표 또는 의사결정자 |
| 입력 데이터 | `0621_meta_ad_report.csv` |
| 출력 형식 | 핵심 요약 / 주요 지표 해석 / 광고 소재별 비교 / 우수 세그먼트 / 비효율 세그먼트 / 예산 조정 / 다음 액션 / 확인 필요 항목 |

LLM이 수행해야 하는 핵심 작업은 전체 성과 요약, 광고 소재별 성과 비교, 연령/성별 세그먼트 해석, 전환 지표 연결 판단, 예산 조정 제안, 데이터 부족 항목 분리이다.

## 3. 분석 대상 데이터

- 원본 파일: `B1-1/docs/0621_meta_ad_report.csv`
- 보고 기간: 2026-06-01 ~ 2026-06-21
- 분석 단위: 광고 이름, 연령, 성별
- 첫 번째 데이터 행: 전체 합계 행
- 이후 행: 광고 이름 × 연령 × 성별 기준 세부 행

수치 검증 기준표는 `B1-1/docs/ad_report_answer_key.md`를 사용했다. 이 기준표는 `B1-1/docs/generate_ad_report_answer_key.py`가 원본 CSV를 직접 읽어 생성한 값이다.

## 5. 동일 입력 프롬프트

모든 모델에는 `B1-1/docs/llm_model_comparison_plan.md` 4.3절의 최종 테스트 프롬프트를 사용했다.

핵심 조건은 다음과 같다.

- 퍼포먼스 마케팅 애널리스트 관점으로 분석
- 전체 성과 5줄 이내 요약
- 광고 소재별 성과 비교
- 연령/성별 기준 우수·비효율 세그먼트 구분
- CTR, CPC, 랜딩 페이지 조회, 제품 맞춤 주문, 등록 완료, 구매 연결 해석
- 예산 확대, 축소, 추가 테스트 후보 구분
- 8개 섹션 구조로 출력
- CSV에 없는 내용 추측 금지
- 빈 셀을 임의로 0으로 단정 금지
- 원인을 단정하지 않고 확인 필요 항목 분리

동일 입력 프롬프트 전문:

```text
너는 퍼포먼스 마케팅 데이터를 분석하는 마케팅 애널리스트야.
첨부한 메타 광고 성과 CSV를 읽고, 우리 서비스의 광고 성과를 의사결정자가 이해하기 쉽게 정리해줘.

[분석 대상]
- 파일명: 0621_meta_ad_report.csv
- 보고 기간: 2026-06-01 ~ 2026-06-21
- 데이터 기준: 광고 이름, 연령, 성별
- 첫 번째 데이터 행은 광고 이름/연령/성별이 비어 있는 전체 합계 행으로 간주해줘.
- 이후 행은 광고 이름, 연령, 성별별 세부 성과로 간주해줘.

[분석 요구사항]
1. 전체 성과를 5줄 이내로 요약해줘.
   - 총 지출, 도달, 노출, 링크 클릭, CTR, CPC, 랜딩 페이지 조회, 등록 완료, 구매를 중심으로 정리해줘.
2. 광고 소재별 성과를 비교해줘.
   - 01_edu_ad1
   - 02_memory_ad1
   - 03_100books_ad1
3. 연령/성별 기준으로 성과가 좋은 세그먼트와 비효율적인 세그먼트를 구분해줘.
4. CTR, CPC, 랜딩 페이지 조회, 제품 맞춤 주문, 웹사이트 등록 완료, 웹사이트 구매를 연결해서 해석해줘.
5. 광고 예산을 늘릴 후보, 줄이거나 중단할 후보, 추가 테스트가 필요한 후보를 구분해줘.
6. 다음 광고 운영에서 취할 액션을 3~5개 제안해줘.
7. 데이터가 부족하거나 해석에 주의가 필요한 부분은 "확인 필요"로 따로 정리해줘.

[출력 형식]
## 1. 핵심 요약
## 2. 주요 지표 해석
## 3. 광고 소재별 비교
## 4. 우수 세그먼트와 근거
## 5. 비효율 세그먼트와 근거
## 6. 예산 조정 제안
## 7. 다음 액션 제안
## 8. 확인 필요 항목

[금지 사항]
- CSV에 없는 내용을 추측하지 마.
- 빈 셀을 임의로 0이라고 단정하지 마.
- 실제 수치와 다른 값을 만들어내지 마.
- 근거 없는 마케팅 조언을 일반론처럼 쓰지 마.
- 계산이 필요한 경우 어떤 지표를 기준으로 판단했는지 밝혀줘.
- 원인을 단정하지 말고, 데이터로 확인되는 현상과 추정이 필요한 해석을 구분해줘.
- 고객의 심리, 광고 문구의 의도, 랜딩페이지 품질처럼 CSV에 없는 정보는 "확인 필요"로 분리해줘.

[작성 방식]
- 표와 bullet을 함께 사용해 읽기 쉽게 작성해줘.
- 중요한 수치는 원본 CSV 기준으로 함께 적어줘.
- 최종 결론은 의사결정자가 바로 볼 수 있게 간결하게 작성해줘.
```

## 6. 평가 기준

| 번호 | 평가 축 | 평가 기준 |
| --- | --- | --- |
| 1 | 데이터 이해 정확성 | CSV 구조, 전체 합계 행, 세부 행, 광고명, 연령, 성별을 올바르게 이해했는가 |
| 2 | 수치 해석 정확성 | 전체 수치, 소재별 수치, CTR, CPC, 전환 지표를 실제 값과 다르게 말하지 않았는가 |

## 8. 모델별 결과 요약

### 8.1 GPT-5.5

GPT-5.5는 전체 합계와 소재별 합산값을 기준표와 거의 동일하게 인용했다. 총 지출 149,488원, 클릭 294건, CTR 3.00%, CPC 508원, 랜딩 조회 274건, 등록 35건, 구매 6건을 정확히 제시했다.

광고 소재별로도 `01_edu_ad1` 지출 51,398원·클릭 72건·구매 6건, `02_memory_ad1` 등록 14건, `03_100books_ad1` 클릭 140건·CPC 336원 등 핵심값이 기준표와 일치했다.

빈 셀 처리도 가장 안정적이었다. 구매가 기록되지 않은 소재를 단정적으로 "0건"이라고 몰아가기보다 "기록된 구매 없음" 또는 "확인 필요"로 분리했다. 다만 세부 소재 × 세그먼트 조합 분석의 깊이는 Claude보다 조금 덜 촘촘했다.

### 8.2 Claude Sonnet 4.6

Claude Sonnet 4.6은 전체 합계와 소재별 수치 대부분을 정확히 읽었다. 특히 소재별 랜딩→등록 전환율, 제품 맞춤 주문이 링크 클릭보다 많은 행, 도달·노출 0인데 랜딩 페이지 조회가 있는 행 등 데이터 이상 징후를 잘 찾아냈다.

인사이트 품질은 가장 강했다. `03_100books_ad1`은 클릭 효율은 좋지만 등록 전환율이 낮다는 점, `02_memory_ad1`은 등록 기준 효율이 좋다는 점, `01_edu_ad1 / 25-34 male`에 구매 6건이 집중되었다는 점을 실무 의사결정과 연결했다.

감점 요인은 빈 셀 처리다. 일부 비효율 세그먼트에서 원본 빈 셀을 `0건`, `전환 없음`처럼 확정적으로 표현했다. 또한 `18-24` 전 세그먼트 총 지출을 약 8,596원으로 제시했으나 기준표 기준 합산값은 7,403원이다.

### 8.3 Gemini 2.5 Pro

Gemini 2.5 Pro는 전체 합계 수치는 대체로 맞췄다. 총 지출 149,488원, 클릭 294건, CTR 3.0%, CPC 508원, 랜딩 조회 274건, 등록 35건, 구매 6건은 기준표와 일치했다.

하지만 소재별 합산값에서 핵심 오류가 많았다. `01_edu_ad1` 지출을 50,210원으로 썼지만 기준값은 51,398원이고, 클릭도 71건으로 썼지만 기준값은 72건이다. `02_memory_ad1` 지출도 49,507원으로 썼지만 기준값은 51,007원이다.

가장 큰 문제는 존재하지 않는 데이터 불일치를 만든 점이다. Gemini는 세부 항목의 등록 완료 합산이 36건이고 전체 합계 35건과 다르다고 했지만, 기준표 생성 스크립트 기준 세부 행 합산과 전체 합계는 모두 35건으로 일치한다. 또한 CSV에 매출액이 없는데 소재별 ROAS를 추정한 점도 환각에 해당한다.

## 10. 최종 선정 모델

### 최종 선정: GPT-5.5

최종 선정 모델은 **GPT-5.5**이다.

GPT-5.5는 최종 평균 4.79점으로 3개 모델 중 가장 높았다. 특히 이번 과업의 핵심 평가 축인 데이터 이해 정확성, 수치 해석 정확성, 환각 억제에서 모두 5.0점을 기록했다.

원본 CSV 기준표와 비교했을 때 GPT-5.5는 전체 합계, 광고 소재별 합산값, 주요 세그먼트 수치를 가장 안정적으로 맞췄다. `03_100books_ad1`의 클릭·랜딩·CPC 강점, `02_memory_ad1`의 등록 효율, `01_edu_ad1 / 25-34 male`의 구매 집중도 기준표와 맞게 설명했다.

또한 빈 셀을 임의로 0으로 단정하지 않고, 구매 편중이나 전환 추적 문제를 확인 필요 항목으로 분리했다. 광고 데이터 해석 업무에서는 그럴듯한 인사이트보다 수치 신뢰성과 환각 억제가 더 중요하므로 GPT-5.5를 최종 모델로 선정한다.

## 11. Claude Sonnet 4.6과의 비교

Claude Sonnet 4.6은 최종 평균 4.43점으로 GPT-5.5에 근접했다. 인사이트 품질과 보고서 문장 품질은 매우 좋았고, 데이터 이상 징후를 찾는 능력도 뛰어났다.

다만 일부 빈 셀을 0건처럼 단정한 점과 `18-24` 합산 지출 오류가 있어 수치 검증 중심 업무에서는 GPT-5.5보다 낮게 평가했다. 세부 분석의 깊이를 우선하는 상황에서는 Claude Sonnet 4.6도 좋은 대안이지만, 최종 제출용 분석의 기준은 수치 정확성과 환각 억제이므로 GPT-5.5가 더 적합하다.

## 12. 한계와 개선 방향

- 이번 비교는 단일 CSV와 단일 프롬프트 기준이므로, 반복 실행 시 점수 일관성은 추가 확인이 필요하다.
- Gemini 2.5 Pro의 오류가 API 입력 방식 때문인지 모델 자체의 표 처리 문제인지는 추가 테스트가 필요하다.
- 빈 셀 처리 기준을 프롬프트에 더 강하게 명시하면 모델 간 환각 차이를 줄일 수 있다.
- 최종 보고서에는 `ad_report_answer_key.md`처럼 원본 CSV에서 직접 생성한 기준표를 함께 두는 것이 좋다.
- 향후에는 모델 출력에서 수치만 자동 추출해 기준표와 비교하는 스크립트를 만들면 평가자의 주관 개입을 더 줄일 수 있다.
