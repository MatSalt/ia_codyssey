# AI 코딩 도구 사용 과정 — 대화 발췌

도구: Codex. 아래는 실제 이 작업 대화에서 발췌한 사용자 요청과 진행 내용이다. API 키와 인증정보는 포함하지 않는다.

## 1. 과제 파악

사용자: “과제 서브젝트 읽고 어떤 과제인지 파악해. 보너스는 안할거니까 고려하지마. 파악하고나서 간단하게 시도해보기 좋은 아이디어 10개 추천해줘”

Codex: PDF의 필수 8개 기능 요구사항, 바닐라 프론트/Python 백엔드/Vercel 배포와 제출 5종을 정리했다.

## 2. 서비스 선택과 계획

사용자: “영어 글 넣으면 a1~b2 레벨로 변환해주는 영어학습 코치 프로그램”

사용자: “작업 계획 세우고 나한테 검토 받아”

Codex: 작업 계획을 작성하고 사용자 검토를 받았다.

## 3. 요청 방식과 모델 선택

사용자: “한 번에 A1·A2·B1·B2 모든 출력을 기대하는 방식과 각각 별개로 요청하는 방식을 비교해줘”

Codex: 비용·대기·학습 목적을 비교한 뒤 한 번에 네 수준 생성과 결과 탭 전환을 제안했다.

사용자: “그럼 이 프로젝트에서 jev는 사용 안할게. 다만 시작은 gemini 무료 api로 할게”

Codex: Gemini 무료 구간, Jev 제외, 추가 호출 없는 탭 방식으로 계획을 수정했다.

## 4. 요구사항 대조와 구현 승인

사용자: “과제 문서에 있는 기능 요구사항이 계획에 잘 반영되어있는지 검토해”

Codex: 필수 8개 항목을 대조하고 타겟 정의, 키 유출 대응, 구조 설명, 외부 접속 검증을 보완점으로 제시했다.

사용자: “계획서대로 작업 진행시켜”

## 5. 구현과 검증

Codex: “입력 검증과 Gemini 오류 처리를 포함한 백엔드 테스트 15개가 통과했습니다. 지금은 실제 브라우저에서 모바일 화면, 네 레벨 탭 전환, 오류 후 재시도 흐름을 확인하고 있습니다.”

Codex: “설정된 키로 Gemini 실제 호출이 성공했고, 네 레벨과 한국어 설명이 반환됐습니다. 첫 결과에서 ‘추천했다’를 ‘주었다’로 바꾸는 의미 차이가 보여, 이런 행동의 차이도 보존하도록 변환 지시를 보완하겠습니다.”

최종 테스트 수와 실제 호출·배포 확인 결과는 `../verification.md`에서 확인한다. 이 발췌는 전체 대화의 원문 내보내기가 아니라, 과제 과정과 관련된 실제 대화의 선별 기록이다.
