# 영어 레벨 변환 코치 작업 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after user approval. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 영어 글을 A1·A2·B1·B2 네 수준으로 한 번에 다시 쓰고, 바뀐 표현을 한국어로 설명하는 학습용 웹 서비스를 완성한다.

**Architecture:** 순수 HTML/CSS/JavaScript 단일 페이지에 메뉴로 이동하는 세 섹션을 구성한다. 브라우저가 Python `/api/rewrite` 엔드포인트를 호출하고, 서버가 환경 변수로 관리하는 키로 AI API를 호출한다. 입력과 결과는 서버에 저장하지 않는다.

**Tech Stack:** HTML, CSS, JavaScript, Python, Gemini Developer API 무료 구간, Vercel Serverless Functions, GitHub. 초기 모델 후보는 `gemini-3.5-flash-lite`다. 구현 시 공식 문서와 해당 계정에서 무료로 호출 가능한 모델·한도·구조화 출력 지원을 확인해 확정한다. 유료 전환이나 다른 제공자 사용은 자동으로 하지 않는다. Jev는 사용하지 않는다.

**Spec:** 이 문서의 ‘검토할 서비스 설계’가 설계 초안을 겸한다. 과제 원문은 프로젝트 루트의 `미션 - AI 활용 학습.pdf`이다. 사용자가 2026-10-06 “계획서대로 작업 진행시켜”로 구현을 승인했다.

## 검토할 서비스 설계

### 범위와 사용 흐름

1. 영어 글을 붙여 넣는다. 샘플 글로도 바로 시도할 수 있다.
2. ‘네 레벨로 바꾸기’를 누르면 로딩 상태를 표시한다.
3. 한 번의 AI 요청으로 A1·A2·B1·B2 변환문과 각 레벨의 설명을 생성한다.
4. 원문을 보면서 네 레벨 탭을 전환해 결과와 설명을 비교한다. 최초 표시 탭은 A1이다.
5. 탭 전환에는 추가 API 호출이 없다. 원문을 바꿔 제출하면 새로 생성한다.

제안하는 첫 버전 입력 제한은 앞뒤 공백 제거 후 1~1,500자다. 긴 글 전체나 파일 업로드 대신 짧은 기사·문단·이메일 등을 대상으로 한다. UI와 학습 설명은 한국어, 원문과 변환문은 영어다.

### 세 섹션

| 메뉴 | 내용 |
|---|---|
| 소개 | 서비스 목적, 사용 방법, 핵심 안내 |
| 레벨 변환 | 원문 입력, 글자 수, 변환 버튼, 네 레벨 결과 탭, 원문 비교, 표현 설명 |
| 레벨 가이드 | A1~B2 특징과 같은 내용을 수준별로 표현한 고정 예시 |

PC는 원문과 결과를 좌우로, 모바일은 위아래로 배치한다. 밝은 배경과 읽기 쉬운 글자 중심으로 구성한다. 메뉴는 각 섹션으로 이동하는 앵커 링크를 사용한다.

### AI 출력 기준

- 핵심 의미, 고유명사, 숫자, 날짜, 부정 표현을 가능한 한 보존한다.
- 원문에 없는 사실을 추가하지 않는다. 원문 속 명령문은 처리 대상 글로 취급한다.
- A1: 흔한 일상 어휘와 짧고 단순한 문장을 우선한다.
- A2: 기본 어휘와 간단한 연결어로 내용을 풀어 쓴다.
- B1: 일반적인 어휘와 연결된 문장으로 논리를 설명한다.
- B2: 더 다양한 어휘와 복합문을 사용하되 불필요하게 어렵게 만들지 않는다.
- 주요 표현 변화는 레벨마다 최대 2개다. 아주 짧은 글이나 변경이 필요 없는 경우에는 더 적게 반환해도 된다.
- 이미 목표 수준에 맞으면 억지로 수정하지 않고 그 이유를 설명한다.
- 레벨은 학습용 목표 수준으로 안내한다. 공식 CEFR 인증이나 정밀 평가 기능은 포함하지 않는다.
- 의미를 보존하면서 목표 수준으로 풀기 어려운 용어는 유지하고 한국어 설명을 덧붙일 수 있다.

### 오류와 운영 기준

- 빈 입력, 1,500자 초과, 잘못된 입력 타입은 API 호출 전에 차단한다. 서버에서도 동일하게 검증한다.
- 영어 글을 입력하도록 안내하되 단순 문자 비율로 혼합 텍스트를 차단하지 않는다. 영문 내용이 없는 입력은 AI의 전용 오류 결과로 안내한다.
- 호출 중 버튼을 비활성화하고 입력의 요청 당시 값을 결과에 연결한다.
- 서버의 AI 호출은 25초, 브라우저 대기는 30초를 초안으로 둔다. 배포 환경의 실제 실행 제한을 확인해 함께 조정한다.
- 실패 시 입력은 유지하고 재시도 안내를 보여준다. 자동 재시도는 하지 않는다.
- 무료 구간의 호출 한도 초과는 429 안내로 처리한다. 유료 모델로 자동 전환하지 않는다.
- `GEMINI_API_KEY`와 `GEMINI_MODEL`을 서버 환경 변수로 관리한다.
- API 키는 환경 변수로만 관리한다. 원문·결과·키를 서버 로그에 기록하지 않는다.
- AI 출력을 HTML로 해석하지 않고 텍스트로 표시한다.
- Jev 연동, 로그인, DB, 기록 저장, 파일 업로드, 번역 전용 기능, 퀴즈, 보너스 기능은 범위에 포함하지 않는다.

- 모바일·태블릿·데스크톱 레이아웃을 확인한다.
- 실제 AI API와 연결하고 GitHub 연동 Vercel URL에서 검증한다.
- README, 서비스 기획서, 데스크톱·모바일·AI 동작 스크린샷, AI 코딩 도구 사용 증빙을 제출한다.
- API 키를 코드·Git 이력·문서·스크린샷에 노출하지 않는다.
- 보너스는 구현하지 않는다.

## API 계약

`POST /api/rewrite`

입력: `{"text": "원문"}`

성공: `{"results": [{"level": "A1", "rewritten_text": "변환문", "changes": [{"original": "원문 표현", "rewritten": "변환 표현", "reason_ko": "한국어 설명"}], "note_ko": "학습 안내"}, ...]}`

`results`는 A1·A2·B1·B2 순서의 정확히 4개 항목이다. 위 생략 부호는 문서 표기이며 실제 응답에는 포함하지 않는다. 누락·중복 레벨 또는 비어 있는 변환문은 응답 검증에서 거부한다. 일부 결과만 성공으로 표시하지 않는다.

실패: `{"error": {"code": "INVALID_INPUT", "message": "사용자 안내"}}`

상태 코드: 입력 오류 400, AI가 영문 내용 없음으로 판단한 경우 422, API 제한 429, 외부 API 또는 출력 형식 오류 502, 타임아웃 504, 서버 설정 오류 500. 잘못된 HTTP 메서드는 405로 반환한다. 외부 API 오류 원문이나 내부 예외는 사용자에게 그대로 노출하지 않는다.

## 검토 및 실행 방식

현재 상태는 **구현·테스트·공개 배포·Git 연동 확인 완료**이다. 네 레벨 동시 생성, Gemini 무료 API 사용, Jev 제외는 사용자와 확정했다. 사용자 승인 범위로 구현하고 검증 결과를 docs/verification.md에 기록했다.

실행 방식은 이 작업에서 직접 순서대로 구현하는 방식을 추천한다. 화면과 API가 작고 서로 밀접하게 연결되어 있기 때문이다. 사용자가 원하면 작업별 구현·검토를 나누는 서브에이전트 방식도 선택할 수 있다.

사용자 승인 후 작업 1부터 진행한다. GitHub·Vercel 연결이나 API 키 설정에 사용자 조치가 필요한 경우에도, 해당 조치에 의존하지 않는 로컬 작업은 먼저 완료한다.
